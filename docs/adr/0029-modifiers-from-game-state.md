# 修饰键读游戏自己的键盘状态，Win 组合键吞掉

[0026](./0026-faithful-callbacks.md) 按键盘页报来的键名认修饰键：名字里带 `CTRL`、`ALT`、`WIN` 的键一律放行，只认 `SHIFT`。名单是照页面命名习惯推出来的，没有实测样本，后果也记在那里：漏判的代价是一个意料之外的字符。

真机上正是这样漏判的。键盘页报来的是 `value=["A"]`，按住的 Ctrl 不在名字里；游戏自己则在 `InputManager.GetWebModifiers()` 里用物理按键与页面的粘滞键补齐修饰键，再随 `SendKey` 交给页面。插件只看名字，于是把 Ctrl+A 当成字符 `a` 送进输入法，页面收不到这次组合，全选没有发生。Win+空格同理：插件放行，页面按 `Meta+空格` 打出空格。

所以本决定：**修饰键不认名字，改读游戏自己的键盘状态，再叠加一次物理按键的实时读取。带 Ctrl 或 Alt 的键放行给页面，带 Win 的键由插件吞掉，一个字符都不喂。** 游戏的状态每 100 毫秒轮询一次，且含页面开关的粘滞键，所以它是「页面把 Ctrl 打开了」的唯一来源；物理按键用 `GetAsyncKeyState` 现读，补上这 100 毫秒的滞后。键名里的 `CTRL`、`ALT`、`WIN` 仍读一次，作为状态还没轮询到时的兜底。

## Considered Options

- 只认键名（0026 的做法）：实测漏判，Ctrl+A 变成字符 `a`；否决。
- 只读游戏的键盘状态：它每 100 毫秒才更新，同一瞬间按下的修饰键读不到，正是要修的漏判；否决。
- 反射调用游戏私有的 `GetWebModifiers()`：与游戏自己的判断完全一致，但要多一次反射，并押在一个私有方法名上；键盘状态与物理按键都是公开面，够用；否决。
- 读游戏状态加物理按键，并吞掉 Win 组合键：采纳。

## Consequences

- Ctrl+A 之类的组合回到页面，由 Chromium 自己执行；插件仍然不解释组合键。
- Win 组合键在插件这一层消失：Win+空格不再往输入框打空格。代价是 VR 里按 Win+空格不会切换输入法，切换仍由系统完成，插件只是不再添乱。
- 只带修饰键的按下仍交给页面：游戏要先把它记下来，随后的组合才认得出来。插件吞掉的只是带 Win 的完整组合。
- 修饰键的判定与游戏自己的 `SendKey` 判定来自两处代码，理论上可能不一致；两处读的是同一份公开状态，偏差只会落在那 100 毫秒的窗口里。
- 100 毫秒的滞后仍在：修饰键与字符落在同一个轮询窗口里按下又松开时，插件按「没按」处理，与游戏一致。
