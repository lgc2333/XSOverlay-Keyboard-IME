# 组字串的选区跟随输入法

[0019](./0019-inline-preedit-in-composer.md) 把组字串临时拼进 composer，光标跟在编码之后。真机上这条有一个后果：组字期间按左右方向键，输入法在自己那串编码里移动光标，页面上的光标却一直停在编码末尾，用户看不出按键有没有生效。

组字串是输入法的东西，光标位置也是它报出来的。IngameIME 的 pre-edit 回调一直带着组字串里的选区（`selStart`、`selEnd`），插件此前把它丢掉了。

所以本决定：**把输入法报出的选区一路送到 composer，光标画在输入法说的位置。** `ImeContext` 的 pre-edit 回调带出选区，`CompositionView` 与载荷带上它，页面按 `baseStart + selStart` 设置输入框的选区。

## Considered Options

- 光标固定在编码末尾（0019 的现状）：方向键的效果看不见，用户以为按键没生效；否决。
- 组字期间把光标键交回页面，靠「光标一动就取消组字」掩盖：等于把输入法的编码操作换成取消，用户丢掉已打的编码；否决。
- 跟随输入法报出的选区：采纳。

## Consequences

- 光标是画出来的，不是页面自己算的：输入法说在哪就在哪，插件不解释方向键。
- 输入法不报选区、或选区越界时退回编码末尾，与 [0019](./0019-inline-preedit-in-composer.md) 一致。
- 方向键不改变组字的语义：移动光标后按空格只转换光标前那一段，组字继续，其余编码仍在输入法里。控制台探针实测「nihc → 左方向 → 空格」之后组字串是「你hao」、候选是 hao 那一页，与桌面上的输入法一致。
