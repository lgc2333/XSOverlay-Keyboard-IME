# 忠实汇报输入法的回调，按键按组字状态路由

[0025](./0025-respect-ime-mode.md) 的方向是「插件不切中英」，判据读 IMM32 的 `IME_CMODE_NATIVE`。这个判据有一个从未验证的前提：插件得在自己的组字宿主窗口上拿到输入上下文。拿不到，判据就永远读不出「组字」，插件永不接管，比它要修的故障更糟。

换一个角度看，判断中英只是为了回答「这一个键该不该接管」。而接管的目的是把键送进输入法，输入法本来就会回答按键的下场：组字了，它用回调报组字串、候选与提交；没组字，字符以 `WM_CHAR` 落到组字宿主的窗口。既然结果由输入法上报，插件就不必替它预判。

所以本决定：**插件不判断中英，不读也不写任何输入法模式，只按「输入法是否正在组字」路由按键。** 组字中所有键都归输入法，翻译不出的键名直接丢弃，不落到键盘页；不在组字时，只接管单按、且键盘页算出的字符是一个非空格字符的键，其余一律放行给键盘页。输入法原样送出的字符写回 composer 输入框后立刻结束会话。

## Considered Options

- 读 IMM32 的判据（[0025](./0025-respect-ime-mode.md) 的方案）：要先验证输入上下文读得到，还要把判据缓存到组字宿主的线程上并处理过期。判据一旦过期且偏向「直通」，键盘页就自己打英文，正是本次要修的故障；否决。
- 先送进去，再看它组不组字，然后把字符取回：采纳，但只对会产生字符的键成立。方向键、退格、Tab 不产生任何回调，没有东西可以取回，所以它们不能走这条路。
- 把控制键也接管，自己实现一套文本编辑：与 composer 输入框的所有权冲突，还要自己处理光标、选区与撤销；否决。

## Consequences

- 换输入法的成本降到零：不依赖 IMM32，不依赖 CUAS 替 TSF 输入法作答，也不依赖输入法的键位配置。
- 英文态下每个字符都要经过一次组字会话：抢前台、送键、还前台。中文态的成本不变。这是忠实汇报的代价，没有判据就没有省掉它的办法。
- 修饰键只认 Shift；带其他修饰键的键一律放行，插件不解释组合键。
- 接管判定在游戏主线程上读组字状态，而状态在组字宿主的线程上更新。队列里还有没处理完的键时按「组字中」处理，否则快速连打时空格会被判成非组字，漏掉那一次提交。
- 空格与回车在非组字时放行，仍由键盘页处理。
- 组字会话仍然等于一次组字：提交结束它，原样送出的字符写回后也结束它，按键结束后输入法已不持有组字也结束它。漏掉任何一条都会让闸门退化成「只收提交键」，那正是上一版在真机上打不出中文的原因。
- 模式回调、开闭隔间、模式映射与 IMM32 的判据代码整段删除。
- 喂键之后不再停顿。上一版在每次 `SendInput` 后停 120 毫秒，那是为「送完立刻读状态」准备的；状态不再读了，停顿时一并取消。这一点没有真机验证，第一次部署要专门看连续快打时组字会不会提前结束。
- 组合键的修饰键名单是按键盘页的命名习惯推出来的，没有实测样本。漏判的代价是组合键里的字符被送进输入法，表现是一个意料之外的字符；发现新名字时补进名单即可。
