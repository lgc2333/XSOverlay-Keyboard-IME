# 组字前读模式，按需翻转输入法

[0015](./0015-ime-open-compartment.md) 的做法是组字前无条件把 `GUID_COMPARTMENT_KEYBOARD_OPENCLOSE` 置 1，结束再写回原值。实测该隔间在小狼毫上是**翻转开关，不是设定值**：同一个值连写两次，输入法模式翻转两次（写 0 组字、再写 0 直通；写 1 组字、再写 1 直通）。所以「置 1 强制打开」并不成立，它只是在本机默认英文、且每次会话恰好写一次、结束再写回一次这个精确配对上碰巧成立。改为先读宿主报告的输入法模式，只在读到直通时翻转一次，并等回调确认。

## Considered Options

- 无条件写隔间，见 [0015](./0015-ime-open-compartment.md)：不是设定而是翻转；用户本来就在中文时会被翻成英文；异常退出没走到还原，模式被永久留在翻转后的状态；否决。
- 合成 Shift 切换：实测有效（按一次由直通变组字），但能否切换取决于输入法的键位配置，换一个输入法即失效；否决为主路径，只作降级兜底。
- 不强制，由用户自己切：中英键（[0012](./0012-synthesized-modifier-key.md)）尚未落地，删掉强制后 VR 里只剩英文；否决。
- 读输入法模式，按需翻转：采纳。

## Consequences

- 判断依据从「猜机器默认状态」变成「读当前状态」，不再依赖默认输入法。
- 翻转时写与当前值**相反**的值，保证隔间的值真的变化；同值写入是否触发翻转取决于输入法，不可依赖。
- 宿主报告的 `InputMode` 按实测语义使用：`AlphaNumeric` 表示按键会进组字，`Native` 表示原样直通。必须等到该回调到达再判定，紧接切换后的同步读取仍是旧值。
- 翻转后模式没变时只记一条警告并继续：按键会原样直通成明文，不会被吞掉。
- 结束时不还原，用户的输入法模式保持组字结束后的状态。
