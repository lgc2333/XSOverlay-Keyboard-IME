# 尊重输入法自己的中英状态，不自动切换

[0015](./0015-ime-open-compartment.md) 在组字前无条件写隔间；本条此前改为「读宿主报告的输入模式，只在读到直通时翻转一次」。该判据实测不成立：宿主报告的 `InputMode` 与中英无关，组字进行中仍报直通，XSOverlay 启动后的首键也被判成「已在组字」，字母被原样插成英文。

可用的状态源只剩一个：IMM32 的 `ImmGetConversionStatus`。它经 CUAS 层替 TSF 输入法作答，读 `IME_CMODE_NATIVE` 就是「这个键会不会组字」。探针在小狼毫上实测：英文态 `conversion=0xca0 native=False`，切到中文后 `0xca1 native=True`，此后七次采样一致。

所以本决定：**插件不切换中英**。输入法是什么状态，按键就按什么状态走；中英由用户显式切换。

## Considered Options

- 自动翻转（本轮先实现过一版）：用户主动切到英文后，第一键又被翻回中文，英文根本打不出来；否决。
- 读 TSF 转换模式隔间：小狼毫只在该隔间自身变化时刷新它，值与真实中英无关；IngameIME 读的就是它，也是这次故障的来源；否决。
- 读 TSF 开闭隔间：小狼毫在该隔间的回调里把 `ascii_mode` 取反后 `_SetKeyboardOpen(true)` 写回 1，隔间常住 1，值只在变化瞬间有信号；否决。
- 读语言栏按钮：`GetStatus` 只有启用/隐藏标志，`GetText` 是固定字符串，中英只体现在图标里；否决。
- 读 IMM32 的 `IME_CMODE_NATIVE`：实测跟随真实状态；采纳。
- 判据读不到时也接管：会把用户的英文吞成拼音；否决，改为不接管、交给页面自己打。

## Consequences

- 接管判定只有两档：输入法在原生态时接管能起组字的字符键，组字中接管所有键，其余一律还给页面。
- 直通一旦出现，字符写回页面并立即结束会话，不再逐键抢前台。
- 首键不会再把英文翻成中文；切中英要用户自己动手，控件形态留给后续实验，不在本条决定内。
- 状态按线程读：插件在自己的 STA 线程上读自己的宿主窗口，不跨线程查询。
- 判据依赖 CUAS 对 TSF 输入法的实现；换一个不实现它的输入法，结果是「不接管」，不会被吞键。
- 与 [0012](./0012-synthesized-modifier-key.md) 的关系待定：切中英的控件若落在页面上，布局里合成了中英键就不再必要。
