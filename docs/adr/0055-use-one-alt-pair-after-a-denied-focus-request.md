# 新聚焦请求被拒后允许一次 Alt 配对

真实 VR 首次获取前台被系统拒绝，换主线程单次调用也有拒绝样本；Alt 配对后已在原 Unity 隐藏宿主取得前台，并完成原页面切拼音、首 A 组字、Return 提交及档案与原前台恢复，见[首次前台获取](../archived/notes/foreground-acquire.md)。用户选择采用此方向，接受全局输入与不可保证回滚的风险，不再扩展其他资格候选矩阵。

修订 [0050](./0050-hold-the-host-focus-for-the-composer.md) 的首次获取规则：每个新的明确聚焦期先正常请求一次；仅在失败、原前台和请求来源未变、目标仍有效且没有按住键或活动菜单时，插入一批 Alt down/up。只有两条均成功插入才再请求一次，并核验实际前台与宿主线程焦点。任何失败即停止并撤销本次资格，不循环重试或盲目补键。此分支不放进每键 Ensure，也不供已撤销的旧工作重新获取；成功后沿用 0050 的焦点期寿命与条件归还。

SendInput 成批串行不等于事务：部分插入无法保证自动恢复，全部插入也不证明处理完成或原窗口没有菜单、修饰键副作用。用户接受这一剩余风险；失败仍保留手动桌面恢复路径，不承诺任意环境都能获取。

用户主动切走后再明确点回输入框，第一次点击就应恢复输入；不能用保守拒绝新操作、要求再点一次来回避同步。旧消息自动抢回前台仍禁止。现有裸 composer-active 尚不能同时证明这两点，来源与撤销的接线仍须验证；此决定没有选定该协议。

这是已接受、待实施验收的策略。剩余关键验证为真实 VR 首动作、自然失焦后的旧工作拒绝和原前台菜单/修饰键观察；现有临时探针不代表完整 0050 生命周期或产品实现。
