# 修饰键的粘滞跟随宿主，失焦时全部复位

[0036](./0036-one-table-for-key-ownership.md) 把组字期间的单按 Shift 与 Caps 交给了输入法。上一版这一篇反过来，把它们**全留在页面**，由页面把字母换成大写再当字符送进输入法。真机两件事不对：

- CapsLock 在输入框里打不出大写，按过之后也取消不掉；Shift 的粘滞被打断，组字时没法再打大写字母。
- 页面与宿主各记一份修饰键状态：页面说「按着」，宿主那边永远是「没按」，输入法看到的是没有修饰键的按键。

本决定：**修饰键的粘滞落到宿主窗口的真实按键状态上；窗口失焦就全部复位；Caps 跟随系统。**

1. 页面发来 Sticky 的 Shift、Ctrl、Win 按下，插件在宿主窗口**真的按下**那个修饰键，并**保持按住**；页面再发一次或发出抬起，插件才送抬起。黏住就是黏住：宿主、系统输入法与插件看到的是同一个「按着」。
2. Caps 不合成。它是系统级锁定，页面只读、只显示，按下时交回系统；插件不替它按，也不在失焦时把它复位。
3. 宿主窗口失焦（页面报来 composer 失活、别的浮窗抢走焦点、键盘关闭）时，插件把自己按下的修饰键**全部抬起**，回到「没按」；Caps 不动，跟随系统。
4. 切输入法（Win+空格、下拉框、中英切换键）不替输入法上屏。切换时正在组的那一段怎么收尾是输入法自己的事，丢掉也是预期结果；插件只在切换稳定后重读名字、图标与组字状态，保证画出来的和输入法里的一致。
5. 这一条之外的一切仍按 [0036](./0036-one-table-for-key-ownership.md) 的表走。

## Considered Options

- 上一版（页面自己算大写、修饰键不喂）：宿主状态永远不按，Caps 失效，输入法看不到修饰键；否决。
- 只发按下、不发抬起：页面失焦或键盘关闭后修饰键永远卡住；配上复位规则才算完整，不是独立方案；否决。
- 修饰键跟随宿主、失焦全部复位、Caps 交回系统：采纳。

## Consequences

- 组字中按 Shift 现在是**真的按住**：输入法收到的是带 Shift 的按键。Rime 里 Shift 单按仍可能是它自己的切换键，行为待实测。
- 按住 Win 期间任何键都成了 Win 组合，[0036](./0036-one-table-for-key-ownership.md) 里「带 Win 的按下吞掉」在按住状态下的含义变了，实现时要重新确认，待实测。
- 失焦复位必须真的送抬起。少了这一步，回到游戏后每个键都会带着修饰键。
- 插件喂键会 `AttachThreadInput`，该调用重置 `GetKeyState`/`GetKeyboardState` 看到的状态，「按着」不能只靠读这个判断，实现前先量。
- 组字中切输入法，正在打的编码会丢，或者由旧输入法自己上屏；插件不替它上屏。要不要保留这一段不是插件能替用户决定的事。
- 切换后的状态由插件重读：系统不保证给宿主窗口发 `WM_INPUTLANGCHANGE`，所以喂完 Win+空格 起一个 400 毫秒的一次性定时器；组字在切换稳定后也单独重读一次，页面不会继续画输入法已经不持有的编码。
