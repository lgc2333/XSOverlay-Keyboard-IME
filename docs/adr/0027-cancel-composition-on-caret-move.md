# 组字期间 composer 输入框的光标一动就取消组字

[0019](./0019-inline-preedit-in-composer.md) 把组字串临时拼进 composer 输入框，并记下一条后果：还原依赖组字期间光标位置不变，实际风险是用户用射线点了输入框。

物理键盘下的对照行为是：组字期间点击输入框的其他位置，输入法会取消组字。这一步由编辑控件自己做，光标一动就通知输入法取消，不是输入法自己察觉的。插件的组字发生在组字宿主里，Chromium 的编辑控件不知道，因此不会替我们取消。不取消的后果是组字串留在错误的位置，提交后写回也错位。

所以本决定：**键盘页在组字期间报告 composer 输入框的光标或选区变动，插件据此取消组字。** 取消的做法是把 Escape 送进输入法，与用户自己按 Esc 走同一条路径。

## Considered Options

- 让输入法自己取消：IMM32 的 `ImmNotifyIME` 要先拿到宿主窗口的输入上下文，而那正是 [0026](./0026-faithful-callbacks.md) 删掉的未验证前提；TSF 的 `TerminateComposition` 需要 IngameIME 内部的 composition，公共接口只暴露 `setPreEditRect` 与 `setActivated`。两条都做不到；否决。
- 把光标变动报给输入法：TSF 里这条通道属于文本服务与文档之间的编辑会话，我们的宿主窗口不是文本存储，没有入口；否决。
- 重新计算锚点，把组字串挪到新光标处：输入法对已经打出的编码没有挪位置的概念，只能取消重来；否决。
- 不处理：组字串与提交文本都会落在错误的位置，用户看不出原因；否决。
- 光标一动就取消组字：采纳。

## Consequences

- 键盘页要观察 composer 输入框的选区与点击；插件收到信号后，在组字宿主的线程上把 Escape 交给输入法，会话随即结束。
- 这条与失焦、关闭键盘页时的取消计划合并成同一条取消路径，都走 Escape。
- [0019](./0019-inline-preedit-in-composer.md) 的拼接与还原逻辑不变，只是还原的触发多了一个来源。
