# 按键归属只有一张表

[0026](./0026-faithful-callbacks.md) 决定「组字中所有键归输入法」，[0029](./0029-modifiers-from-game-state.md) 决定「修饰键单按归页面、Win 组合吞掉」。两条都按**键的形状**分类：是不是修饰键、带不带 Win、有没有字符。它们各自成立，合起来却在三处漏键：

- 组字中单按 Shift / Caps：先撞上「修饰键单按归页面」，永远到不了输入法。小狼毫里这两个键正是 `commit_code` 加切换，用户按了没有任何反应。
- Win+空格：撞上「Win 组合吞掉」，系统收不到这一下，VR 里少了一条切输入法的路。
- 组字中翻译不出的键名：被丢弃，这是对的，但那是归属的结论，不该长成一条独立规则。

本决定：**归属是一张表，四个结论，按顺序判。** 判据在 `Takeover/KeyStrokeReader`，表由单测锁定。

1. 页面发来的不是标准按下 → **页面**。键盘页把修饰键发成 Sticky（LSHIFT、LCONTROL、E05B），把锁键发成 Toggle（CAPITAL），宏发成 Macro；只有第 4 条那个例外由插件接手。
2. Win+空格 → **系统**。插件合成 Win down → Space 下、上 → Win up，切换发生在系统那一侧。实测宿主随后就是新输入法：`小狼毫` → `微软拼音`。
3. 其他任何带 Win 的按下 → **吞掉**：页面不能因为它打出字符，插件也不喂。
4. 输入法正在组字 → **输入法**：单个字符、Sticky 的 Shift、Toggle 的 Caps（键名 CAPITAL）、能翻译的键名都进去；翻译不出的键名吞掉，页面不许在组字串底下改字。带 Ctrl、Alt 的组合仍归页面，[0029](./0029-modifiers-from-game-state.md) 在这一点上不变。
5. 不在组字时，Sticky 的 Shift 与 Toggle 的 Caps 归页面：游戏要记下这一下，随后的组合才成立；插件只在组字期间从页面手里拿走它们。
6. 其余 → **页面**，只有能产出一个字符的按下键由插件接管，这一条是 [0026](./0026-faithful-callbacks.md) 原来的规则。

## Considered Options

- 继续在旧判据上补特例：每来一种键补一个 `if`，Shift、Caps、Win+空格 已经各占一条，下一个键还会再撞；否决。
- 组字中连别的 Win 组合也喂给输入法：Win+R 之类会真的触发系统动作，打一把就弹出运行框；否决。
- 不放行 Win+空格，只留语言栏镜像（[0028](./0028-mirror-the-ime-language-bar-item.md)）：少一条副作用，但用户要的就是以自己的习惯切系统输入法；否决。
- 放行但只改页面显示：输入法本身没换，名字会骗人；否决。
- 一张表、四个结论，输入法归属按是否组字判：采纳。

## Consequences

- Win+空格 切的是**整个桌面**的语言。用户按下时桌面语言一起走，而 VR 里看不见任务栏；实测一次按键能把前台语言从 zh-Hans 切到日语。这是这个选择的代价，接受。
- 组字中按 Win+空格，旧输入法会先把组字**原样上屏**再切走（实测 `COMMIT 'nihao'`）。
- 切换后的输入法与图标由插件自己重读：系统不保证给宿主窗口发 `WM_INPUTLANGCHANGE`，所以喂完 Win+空格起一个 400 毫秒的一次性定时器再读。不等待会读到正在离开的那个输入法。
- 新输入法没有语言栏项时，图标不再保留上一个输入法的图，页面退回自带字形；语言栏项晚到的话，下一次刷新会补上。
- 取消组字不再预判「输入法是否在组字」：那个状态是跨线程读的，判成 false 就把整次取消静默吞掉。没有组字时多送一个 Escape，输入法不吃。
- 组字中 Shift 会把编码原样上屏并切到英文，这是输入法自己的定义；[0026](./0026-faithful-callbacks.md) 的「不替输入法兜底」不变。
- 命中 Win 的其他组合仍然吞掉，[0029](./0029-modifiers-from-game-state.md) 在这一点上继续有效。
