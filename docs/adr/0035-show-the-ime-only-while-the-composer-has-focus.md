# 输入法名字与中英切换只在 composer 输入框有焦点时出现

[0030](./0030-follow-the-foreground-language.md) 让组字线程跟随前台窗口的输入语言：读前台线程的布局句柄，在本线程 `ActivateKeyboardLayout`，名字变了还会 `ActivateLanguageProfile`。它解决的现象是「在游戏里按了 Win+空格，VR 键盘不跟」，代价是常驻轮询任意前台窗口，并在本线程重新激活输入法档案。

[0009](./0009-profile-scope.md) 已经把范围限定在本线程：输入法档案按线程保存，跨进程读不出「用户此刻在用哪个输入法」，所以 [0030](./0030-follow-the-foreground-language.md) 只能跟到语言这一层。同一语言下换输入法时，名字与组字都会落后；要察觉就得在本线程重新激活一个档案，那就成了替用户挑输入法。

本决定：**界面只显示本线程真正在用的输入法；这份信息只在 composer 输入框拿到焦点时出现，其余时候既不显示也不读取。插件不读任何其他程序。**

- 名字：`ITfInputProcessorProfiles::EnumLanguageProfiles` 列出当前语言的档案，取 `fActive` 为真的那一个，再读它的描述。同一语言下的两个输入法共用键盘布局，只有这个标志分得开，所以取到的是正在用的那个，而不是默认的那个。读不到时退回该语言的默认档案，再退回语言名。
- 出现与消失：页面报来 composer 输入框的焦点变化，宿主据此显示或隐藏名字与中英切换按钮；失焦时把切换键从布局里拿走，空格恢复原宽。关闭键盘页按失焦处理。
- 不轮询：只在自己线程的事件上做事——页面报来的焦点变化、宿主窗口的 `WM_INPUTLANGCHANGE`、切换键点击，以及每次喂键之后读一次图标（喂进去的 Shift 可能就是输入法自己的切换键）。失焦期间一次也不读。
- 删掉的东西：400 毫秒定时器、前台线程的 `GetKeyboardLayout`、`ActivateKeyboardLayout`、`ActivateLanguageProfile`。

## Considered Options

- 继续跟随前台（[0030](./0030-follow-the-foreground-language.md)）：要读别的线程、写本线程档案，同一语言换输入法仍然错；否决。
- 只跟游戏窗口的语言：源更窄，但仍要改本线程档案，且 VR 里「此刻的前台是不是游戏」未验证；否决。
- 显示该语言的默认档案名字：实现更短，但同一语言换过输入法时就显示错的那个；否决。
- 显示语言名而不是输入法名：最保守，但对用户没有用——他要的是这台键盘在用哪个输入法，之后还要做成切换下拉；否决。
- 只在输入框获得焦点时读一次前台再跟随：本质还是 `ActivateKeyboardLayout`，做不到不碰档案，且那一刻的前台不一定是游戏；否决。
- 只显示本线程的输入法、只在有焦点时出现、纯事件驱动：采纳。

## Consequences

- 游戏里按 Win+空格 不再影响 VR 键盘。[0030](./0030-follow-the-foreground-language.md) 修的那个现象回到「不跟」，但代价也一起没了：插件不改本线程档案，也不碰别的进程。
- 名字与组字由同一个标志决定，不会再出现「显示一个、组字用另一个」；用户改了系统默认输入法也影响不到这里，因为读的是本线程的活动档案。
- 图标刷新退化为事件驱动：按切换键、语言变化、每次喂键之后各读一次。输入法自己改图而没有这些事件时，图标最多滞后到下一次按键；旧行为是最多 400 毫秒。
- 键盘关着时插件不读任何输入法状态，也不会因为读状态去唤起什么。
- 页面重建输入框不算失焦（[0034](./0034-a-rebuilt-composer-is-not-a-blur.md)）：焦点判断放到下一个任务再算一次，避免重建瞬间误报。
- 失焦时切换键消失、空格恢复宽度，布局会有一格宽的变化；只在用户自己移开焦点时发生。
- 名字为空时 chip 不显示；输入法不注册带图标的语言栏项时，切换键退化为「中/英」字样（[0028](./0028-mirror-the-ime-language-bar-item.md)）。
- 切换下拉还缺两样：按档案切换的 `ActivateLanguageProfile`，以及列出档案的界面。枚举与「哪个是活动的」已经就位，切换之后要重新读活动档案，不能拿默认档案顶替。
