# 候选栏只显示，点选与翻页交给键盘按键

候选栏显示候选、当前高亮与输入法名字，不响应点击；点选第 N 个候选与翻页，用键盘页自己的数字键和 PageUp/PageDown，经接管路径送进组字宿主。理由是合成的按键不可靠：方向键的语义按输入法而变（走一格、翻页、不吃都有可能），合成的键一旦不被接受，后果从组字串多一个字符到提交错候选不等，多数看不见。键位配置本来就是用户熟悉的那套，交给键盘既准确又能自己看见和撤销。

## Considered Options

- 合成按键点选，见 [0010](./0010-candidate-by-keys.md)：要按输入法逐个适配，且无法确认是否生效；放弃。
- 合成按键后先用候选列表的选中项核对，再提交回车：能防写错，但每个输入法都要试错，复杂度高；放弃。
- 候选栏只显示，按键由键盘送出：采纳。

## Consequences

- 输入法 chip 只显示名字，不再承载点选。
- 插件不需要知道输入法属于哪一族，也不为点选合成任何键。
- 用户点不掉候选；选候选要按键盘上的数字键或翻页键。
- 0010 关于合成 VK_DOWN、VK_RETURN、VK_PRIOR、VK_NEXT 的细节不再适用；"候选列表只读"与"需要页内数字键"这两条实测结论仍然成立。
