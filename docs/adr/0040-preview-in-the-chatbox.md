# v1 不在 ChatBox 里做实时预览

路线图的「下一步」想在组字过程中把编码实时显示进 VRChat 的 ChatBox。原型按 800 毫秒节流发过，页面侧也验证通了；但它同时踩到两件事：一是 [0011](./0011-input-only-no-autosend.md) 只允许插件写输入框，二是 **没法把预览收回去**。

收不回去这一点是硬阻碍：游戏的 `VRChatOscService.SendChatboxAsync` 对空白文本直接返回 `invalid_text`，超过 144 字返回 `text_too_long`。发送空串并不能清空 ChatBox；组字结束（上屏、取消、关页）之后，半成品编码会留在那里，直到用户下一次发送或 VRChat 自己覆盖。预览与页面的发送成了两个写者，还留着一条无法收尾的尾巴。

本决定（待批准）：**v1 不做 ChatBox 实时预览**，ChatBox 只在用户按发送键时更新。将来的做法记在这里，届时另开 ADR 修订 [0011](./0011-input-only-no-autosend.md)：

- 预览、手动发送、清理走**同一个出口模块**仲裁，页面独占目标状态；注入脚本只提供组字快照，不另起直调 `SendVRChatChatboxText` 的出口。
- 手动发送优先并撤销旧预览；迟到的预览帧与迟到的清理都不能覆盖或擦掉正式消息。
- 去重要有期限（VRChat 清空后同文可重发）；失败不记成功，重试有界。
- 长度按 UTF-16 单元算 144，且不切断代理对。
- 必须先找到能可靠清空预览的方式，否则不立项。

## Considered Options

- 现在就做预览：发送验证过，但清空无解，组字一结束就留半成品；否决。
- 现在做预览并在结束时补发完整文本：那是替用户发送，正好踩 [0011](./0011-input-only-no-autosend.md) 的核心；否决。
- v1 不做，先把出口、清理与节流的能力补出来：采纳（待批准）。

## Consequences

- ChatBox 只在用户按发送键时更新，路线图「输入过程中同步显示」这一条推后。
- 「正在输入」上报同样推后：它需要 VRChat 的 OSC typing 参数，游戏的 API 目前没有暴露。
- 已经验证的路线留在路线图里：注入脚本能拿到页面自己的 API 模块（同一条连接、同一个 overlay 身份），目标开关状态在 `.keyboard-vrc-toggle` 的 `aria-pressed` 上，只能在发的那一刻现读。
