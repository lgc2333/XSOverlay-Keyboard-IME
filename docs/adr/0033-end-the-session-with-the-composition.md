# 会话只随组字结束，空格与回车不结束它

会话的结束条件一直是三条：提交、原样送出的字符写回、输入法不再持有组字。此外代码里还有一条：空格与回车本身结束会话。它来自「空格回车是提交键」这个假设，而输入法不认这个假设。

实测：`nihc` 之后按左方向键，输入法把组字串重建成原始编码、光标停在 `ni` 之后；此时按空格，输入法只把光标前那一段转换成「你」，组字串变成「你hao」并继续组字。插件却因为「空格结束会话」把会话关掉，页面回到空闲，剩下的 `hao` 再也没有人提交，再按空格直接落到页面上。用户看到的就是「候选消失、什么都没上屏」。

所以本决定：**会话只随组字结束，空格与回车不再单独结束它。** 提交照旧由输入法的提交回调结束会话；输入法不再持有组字时也结束。

## Considered Options

- 保留「空格回车结束会话」：分段组字下会吞掉后半段，正是要修的故障；否决。
- 空格之后等一个超时再结束会话：凭猜测结束会话，取消与提交的边界会更模糊；否决。
- 只随组字结束：采纳。

## Consequences

- 输入法若对空格毫无反应、又一直持有组字，会话会一直开着；此时所有键都归输入法，与「组字中」的定义一致。
- 取消（Esc）仍然靠「输入法不再持有组字」结束会话，不依赖提交。
- 提交晚于组字结束的情形由 [0032](./0032-deliver-a-late-commit.md) 兜住。
