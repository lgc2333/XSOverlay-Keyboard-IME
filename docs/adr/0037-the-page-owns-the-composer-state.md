# composer 的状态归页面，组字期间的值与光标归输入法

这几条毛病是同一个洞：composer 的状态有两个写者，却没人说谁拥有。

- 焦点变成了「页面知道、插件也算一遍」，切换键的宽度等插件的答复才缩，聚焦瞬间先撑开再回弹。
- 页面只认 DOM 焦点。点别的浮窗时整块视图失活，却没有 `focusout`，名字与切换键留在原地。
- 组字期间，射线点输入框、点清空按钮都会改 composer 的值或光标。没人认领这些改动，于是组字串留在旧位置、提交写在旧位置。

本决定：**composer 的状态按三句话分工。**

1. **几何与可见性归页面。** 焦点是页面本地事实（DOM 焦点 × 视图是否活动），切换键在 `focusin` 的同一个任务里挂上去，不等插件；它绝对定位、盖在空格的左端，**不参与行的排版**，所以行宽永远不变。插件报来的 composer 状态只决定候选栏里的输入法名字。
2. **组字期间的值与光标归输入法。** 页面每帧记下「输入法应该持有的值」；值或选区任何一方变化，都按取消处理，不按编辑处理。射线点击、清空按钮、其它脚本改值，走的都是这一条。
3. **取消只有一条路径。** 页面发现 → 上报 → 插件送 Escape → 会话结束。插件那侧的跨线程预判已经在 [0036](./0036-one-table-for-key-ownership.md) 删掉，这条路径上不再有静默出口。

## Considered Options

- 继续让插件决定切换键在不在：要等一次 Vuplex 往返，聚焦必然抖一下；视图失活又没有事件可等；否决。
- 页面轮询值或光标：能盖住清空按钮，但要在组字期间一直读 DOM；取消本来就是事件驱动的（`pointerup`、`selectionchange`、`focusout`），多一条轮询只会让两条路打架；否决。
- 给每个控件挂一个取消 handler（清空按钮一个、输入框一个）：XSOverlay 自己的 DOM 会重建，handler 要跟着重建；而且下一个控件又漏一次；否决。
- 按上面三句话分工：采纳。

## Consequences

- 聚焦时键盘不再先撑开再回弹：切换键不占位，空格宽度一个像素也不变，也没有把右 Ctrl 顶出去的可能。输入法名字晚一帧出现。
- 页面把输入框换掉时，焦点会落到被移除的节点上、再把焦点交还 body；页面发现「刚才有焦点的输入框已经不在了」就把焦点交给新输入框，切换键随之重新挂上，组字串也搬进新输入框——换输入框不算失焦（[0034](./0034-a-rebuilt-composer-is-not-a-blur.md)）。页面自己重建时先清状态再换输入框，所以失焦判断留 60 毫秒给焦点回来。
- 提交文本早于组字结束送达时，页面先收掉组字串再插入提交文本，不会把刚写回的内容擦掉。
- 点别的浮窗后名字与切换键消失：`window` 的 `blur` 与 `visibilitychange` 都算失焦。
- 组字期间点输入框、点清空按钮都会打断组字，正在组的编码按输入法的取消路径丢弃。
- 「输入法应该持有的值」是每帧比对出来的，不是劫持 setter：页面不改 XSOverlay 对象，代价是最迟在下一次指针抬起或下次组字帧才发现被改。
- 插件不再决定切换键在不在（[0035](./0035-show-the-ime-only-while-the-composer-has-focus.md) 的这条由页面接管），但名字仍然只在页面报来 composer 有焦点时读取与显示。
- 页面重建输入框不算失焦：本地失活判断仍放到下一个任务，重建时新输入框已经重新拿到焦点。
