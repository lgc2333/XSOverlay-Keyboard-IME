# 首次前台获取

焦点期只正常获取一次前台，规则见 [0050](../adr/0050-hold-the-host-focus-for-the-composer.md)。这里记「首次聚焦后切换输入法无效」的证据与诊断状态。

## 证据

- 真实 VR：同一微软拼音项的初始两次请求，原 `SetForegroundWindow` 都返回 false，调用前后前台都是 `steamwebhelper` 的 `SDL_app`，原 `Take=false`，活动项仍是小狼毫。经 VR 桌面浮窗点击其他普通窗口再回来选择同一项，原调用返回 true，前台切到宿主，活动项真实变为微软拼音（回读档案身份确认）。前两次最后输入 tick 相同，第三次因桌面交互变大；前台窗口与最后输入时间同时改变，两者未隔离。
- 该样本排除了「失败调用先取得前台再被夺走」：原生调用直接返回 false，前台保持原窗口。系统拒绝的具体条件仍未确定。
- 桌面 WebSocket 自测三次请求均返回 false，前后前台属于其他进程（含 VSCode），活动档案未变。该入口没有给游戏带来真实桌面输入，不能代替 VR 点击，也没有复现旧会话里「焦点往返后第三次成功」的完整对照。
- 被动诊断 0.6.0 已在 `ForegroundLease.Take` 的 `SetForegroundWindow` 旁记录参数与返回值，保留原调用、次数与判定；另记目标与前台 HWND/PID/class、调用线程焦点、最后输入 tick，并用进程外前台事件关联。产物已构建，尚未安装。
- 隔离检查把生产 `ForegroundLease` 的 Win32 操作换成固定状态：原生返回 false、true、false 时原 `Take` 分别为 false、true、true，每次恰好调用一次；最后一种在调用前目标已在前台。该检查没有真实改变前台。
- 前台事件记录器已验证能收到三次真实前台事件并在同一线程解除；游戏退出时的清理分支未核对。

- 页面控制探针经原菜单切到微软日语：初次请求同样失败，VR 桌面浮窗交互后原调用返回 true，回读语言 `0x0411` 与对应 service、profile 身份。该对照没有隔离系统拒绝条件，也没有改变原前台调用。

## 解释边界

- 区分三层事实：原生返回值、即时窗口快照、带事件时间的前台通知。原生 false 但目标已在前台时 `Take` 仍可能成功；原生 true 后目标被切走属于另一类问题。单个 false 不解释拒绝原因。
- 前台事件缺失只在钩子有效、未过观察期限且无丢记录时有参考价值；回调时的 PID 与 class 只代表回调时状态。
- `GetLastInputInfo` 只属于当前登录会话，不保证 tick 严格递增，也不能单独证明哪个进程收到最后输入。

## 下一步

- 冷启动后依次标记首次请求、用户点击桌面浮窗、再次请求同一项；比较系统直接拒绝与其他窗口夺回，确认真实活动档案后再判定成功。
- 不通过合成 Alt、切换模式或定时重试获取前台；租约寿命调整不能替代该实验。
