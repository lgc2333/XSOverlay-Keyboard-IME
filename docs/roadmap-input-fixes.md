# 六项输入缺陷的落地方案

范围是[路线图](./ROADMAP.md)中的六项输入缺陷。回车地址、系统列表顺序、JIS 按钮与有效专用码接管已实现，真实 VR 验收待完成。证据详见[调查记录](./handoffs/26-11-08-1_roadmap-input-defects.md)，实施只修插件造成的缺陷，保留输入法和系统的原生结果。

| 问题                 | 已确定来源                                          | 实施状态                                                                      |
| -------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------- |
| 微软拼音、日语无输入 | 独立生产宿主中过早归还前台；迟到普通字符未交付      | 原生失焦、后台 Chrome 撤销及 TSF 旧范围对照通过，真实 Vuplex 与物理输入待验证 |
| JIS 专用键           | 插件漏接管有效专用码；安装键的原码解释未闭合        | 标准原生码接管与归属回归通过，真实原码仍需单独验证                            |
| 回车无反应           | 插件模块 URL 缺少 `/apps`，浏览器回归服务器掩盖错误 | 已修正模块与服务器路径，六条页面路由通过，待 VR 验收                          |
| 输入法列表重排       | 插件枚举时把当前语言放在前面                        | 已删除当前语言优先分支，三种语言的独立 STA 对照通过，待真实页面验收           |
| JIS 出现切换按钮     | 插件没有使用物理布局限制                            | 已按 [0049](./adr/0049-hide-the-input-mode-switch-on-jis.md) 实现，待 VR 验收 |
| 首次切换无效         | 请求已到宿主，但首次取前台失败                      | 断点已确定，系统拒绝或前台被夺回仍待区分                                      |

## 实施顺序

回车地址、系统列表顺序、JIS 按钮和有效 JIS 专用码接管已实现。宿主生命周期已按 [0050](./adr/0050-hold-the-host-focus-for-the-composer.md) 接受聚焦期租约，先完成独立原型与物理输入验证，再实施微软输入修复。首次前台失败保持独立诊断，避免把租约寿命调整当作取前台权限的修复。

### 回车

- 修正 [native-keyboard-input](../web/src/native-keyboard-input.ts) 与 [return-feedback](../web/src/return-feedback.ts) 的原页模块地址，使用真实 `/apps/UserInterface/Default/Keyboard/js/` 路径。
- 修正[测试服务器](../web/tests/server.mjs)的模块映射。真实路径提供安装模块，旧路径和未知模块返回 404。
- 保留现有按压、重复、音效、触觉与回车归属，不增加错误后重放按键。
- 验收 DOM Enter、pointer、touch 在空闲与组字时共六种路径。空闲时恰好走一次原发送，组字时恰好请求一次宿主且保持 composer 焦点。
- 隔离测试只证明页面路由。最终在真实 VR 页面核对宿主答复、提交与最终发送，集中安排一次验收。

### 输入法列表

- 从 [ImeProfiles.ListChoices](../XSOverlayKeyboardIme/Ime/ImeProfiles.cs) 删除当前语言优先分支。
- 按系统 `GetLanguageList` 的次序枚举每种语言的 `EnumProfiles`，保留原有类型过滤。
- 每次刷新读取系统列表，选中项按档案身份匹配，不按名称排序，也不缓存自定义顺序。
- 验收同语言切换与跨语言切换前后的档案身份序列；系统枚举不变时，页面顺序必须不变。

### JIS 按钮

- 使用 XSOverlay 实际发布的 `keyboardFormat`，它表示 ANSI、ISO、JIS。`userSettings.format` 表示键区大小，不能替代物理布局。
- 捕获现有布局生成结果并缓存到页面桥，页面就绪时重放；后续布局通知同步更新。沿用既有布局生成操作，避免为了显示按钮额外调用有线程布局副作用的布局查询。
- 在 [switch-key](../web/src/switch-key.ts) 挂载前应用 [0049](./adr/0049-hide-the-input-mode-switch-on-jis.md)。JIS 卸载按钮并恢复空格宽度，ANSI、ISO 沿用图标和焦点条件。
- 验收 JIS 配中文输入项、ANSI/ISO 配日语输入项，以及三种布局之间反复重建。检查按钮数量与空格原宽。

### JIS 专用键

- 按 [0048](./adr/0048-route-jis-ime-keys-through-the-host.md) 扩展 [VirtualKey](../XSOverlayKeyboardIme/Input/VirtualKey.cs) 与 [KeyStrokeReader](../XSOverlayKeyboardIme/Takeover/KeyStrokeReader.cs)。有效专用原生码在单字符判断之前生成一个原码 stroke。
- 以数值身份识别 `KANA=0x15`、`CONVERT=0x1C`、`NONCONVERT=0x1D`，兼容同值枚举别名；不以日文标签推断键码或行为。
- 保持 Standard 样式、Shift、Ctrl/Alt、Win+Space 与其他 Win 组合的现有规则。
- 对空闲、组字两种状态验证名字和数字表示，覆盖空标签、日文标签及误导性单字符，确认只发送一个原码 stroke。
- 当前安装的实际值是平/片假 `70`、無変換 `235`，変換离线重建为 `79`。前两项有现场记录。它们不能直接替代上述标准码，尤其不能把 `70` 当作标准 Kana。
- 标准码接管通过不代表三颗安装按键已修复。继续核对其实际 OS 事件和输入法解释，保留 XSOverlay 扫描码转换证据；不增加标签纠错或输入法特例。
- 下一次真实点击三键时，关联记录原值、`webValue`、插件归属、游戏焦点和最终发送目标。原模拟器将 `70/79` 解释为 F/O，但有焦点路径优先使用日文标签，现有证据尚不能解释现场的全部 `f/a`。

被动追踪已准备，尚未部署。同步游戏调用带关联编号，覆盖原事件、插件判定、原模拟器实参和 `KeyboardInputFocusManager.SendKey` 参数。编号只属于该线程的同步调用，不能绑定稍后到达的宿主或页面消息。页面另记键、输入和组字事件的固定分类及长度；未知原文不会进入诊断记录，捕获阶段的 `defaultPrevented` 也不代表最终取消状态。

同款 Mono 的替代原函数检查覆盖编号嵌套恢复、线程隔离、异常传播和其他补丁抑制原函数。独立 Chromium 检查覆盖正常打字、重复安装、未知文本过滤和监听移除。它们验证诊断自身，不验证实际 JIS 发送或输入法解释。日志输出失败也已验证不改变原函数的返回值、异常和调用次数。

## 微软输入的生命周期

已完成的独立实验分别验证：拼音 A 开始组字，Return 提交后交付并归还前台；日语普通字符到达即交付，然后归还前台。原样路径在同一环境无输出，小狼毫原样正常。

新增固定 A 的直接 TSF 对照中，微软拼音和日语的 `TestKeyDown/TestKeyUp` 均为 `S_OK`、`eaten=false`，因此没有调用 `KeyDown/KeyUp`。同输入项、同上下文的普通送键对照分别产生组字和字符交付。该探针没有错误，但没有证明直接接口能启动输入，也不能据此断言所有直接 TSF 路径不可用。

### 可以保留的机制

- `WM_CHAR` 到达时通知会话，交付输入法放行的完整文本；交付不再依赖下一次 `Send`，也不能把 UTF-16 代理对拆成两次写回。
- 原生 commit 独立交付，继续覆盖晚于组字结束的提交。
- 修饰键释放不重新抢前台，组字结束和按键批次结束不再归还聚焦期租约。
- 单个 STA 管理上下文和窗口，文本与组字回调只回报输入法实际结果。

### 已接受的生命周期

`SendInput` 成功、队列暂空、抬键及 `Composing=false` 都不能证明异步 TSF 已处理完成。只有结果驱动的单字母实验不能覆盖吃键无输出、取消、多字符、代理对和快速连续输入。

按 [0050](./adr/0050-hold-the-host-focus-for-the-composer.md)，composer 聚焦期间隐藏宿主持有电脑前台和键盘焦点，物理键盘也以 composer 为目标。聚焦时正常获取一次，失焦、关闭或宿主退出时结束，不再从每个按键的暂时状态推断归还时刻。

用户操作桌面导致宿主失焦时，原生线程立即撤销送键资格，通知页面同步使 composer 失焦；排队按键不能抢回前台。页面更新经过 Unity 主线程与 Vuplex，窗口过程不等待 DOM 完成。只有新的明确聚焦才重新获取，页面重建不算新的用户聚焦。

失焦按输入法和系统的默认行为结束，不发送 Escape，不强制提交，也不以 `setActivated(false)` 代替窗口失焦。用户观察的小狼毫不提交、拼音提交全拼作为基线验证，不写成输入法特例。输入法实际提交仍归原 composer，失焦后不应丢弃，也不能写到快速重新聚焦后的另一个目标。光标移动、清空等编辑动作的取消规则保留。

长期租约还须处理物理编辑键与快捷键。[HostWindow.Collect](../XSOverlayKeyboardIme/Ime/HostWindow.cs) 丢弃控制字符，窗口过程没有把物理回车、退格或方向键交给页面的路径。另有 Vuplex 通过 Unity `Input` 转发物理按键到其焦点 WebView 的路径，它独立于 XSOverlay 的内部 `KeyboardFocus`。隐藏宿主占前台时 Unity 是否继续收到按键、Vuplex 焦点是否保留，仍须实测；不能仅据隐藏窗口代码断言编辑键失效。

因此原型须同时观察宿主与 Vuplex，核对物理字符是否重复、编辑键是否丢失，以及 Ctrl+A/C/V 的目标。仅延长租约和回传文字不足以承诺完整物理输入。

当前原生窗口未处理焦点丢失；页面失焦会经 60 毫秒检查调用 `RequestCancel`，最终发送 Escape。原型须分开失焦与编辑取消，并保留默认窗口消息处理。现有 `TryAcceptKey` 与 `DrainStrokes` 不按 composer 活动资格拦住旧队列，`Ensure` 可能重新获取前台，这些都要覆盖。提交回调与写回没有焦点期身份，页面又要求当前聚焦；还须验证迟到提交及快速重新聚焦的归属。

独立原生原型已验证：拼音 A 开始组字，真实桌面失焦后自行提交固定 `a`，资格撤销后尝试送键不会夺回前台。小狼毫本轮未进入组字，尚不能验证其不提交的基线。该实验不含真实页面或 Vuplex，编号只是日志字段，快速重新聚焦隔离仍待完成，详见[原型记录](./handoffs/26-11-08-1_roadmap-input-defects.md#聚焦期租约与原生失焦的独立原型)。

### 迟到提交与原生撤销

保留 [0008](./adr/0008-inserttext-writeback.md) 的原生撤销通道。用户不接受用 `setRangeText` 换取失焦写回；只有证明保留撤销确实不可行后，才重新讨论统一丢弃失焦预编辑的退路。当前后台 Chrome 已有成功样本，不采纳该退路，也不新增撤销例外。

生产页面的隔离回归确认，失焦提交被 `focus-lost` 拒绝，稍后还会请求取消。手动注入旧提交回调时，快速重新聚焦后的新预编辑会被替换，重建后的同名输入框也会被认作目标。后两项证明接口缺少来源身份，不是真实 TSF 迟到时序的复现。

实际有窗口的 Chrome 156 关闭测试框架的焦点模拟后，后台 composer 的 `execCommand` 写回、Ctrl+Z 与重做均成功。有效原生对照确认前后台窗口身份，写回前后仍为同一实验前台窗口，区间未记录前台变化；回到原框后 `pa → p → pa`。这证明存在保留撤销的直路，不能直接外推到 Vuplex。

同页另一个文本框持有 DOM 焦点时，仅设置 composer 的选择范围仍会错写那个文本框。后台临时选择原框、写入再恢复原元素的隔离对照成功。生产焦点观察器的 headless 对照中，同一段同步脚本完成这三步未向宿主报告激活；页面活动时，延后一个任务才恢复的阳性控制会报告。异步写回不能直接套用同步结果。页面仍活动时，本地按钮会短暂挂载，不能只检查桥消息。

生产预编辑仍活动时，裸写入会触发值与选择范围保护，异步请求取消。该对照不是有效提交路径；必须按原输入期结束对应预编辑，再执行归属明确的写回，不能清掉新输入期的状态。人工 window blur 只覆盖观察器分支，没有产生真实后台窗口，原生前台、Vuplex 与真实 IME 的组合仍待验证。按钮失焦对照可以撤销、重做，撤销时可能合并先前文字，不能承诺每次提交单独成为撤销单元。

真实 XSOverlay 释放路径先调用 `IWebView.SetFocused(false)`，再通知页面 `.blur()`。已有 Vuplex 日志也记录过 `documentFocused=false` 且 activeElement 仍为 composer。实施前应沿原释放入口验证背景写回，不能借会重新 `SetFocused(true)` 的原 `SendKey` 路径测试。写回必须绑定原页面、原 composer 与输入期，临时 DOM 选择不得重新授予送键资格。

原生 TSF 的合成对照已按 composition 身份保存来源。不同客户身份下，应用可读取和清除已固定的旧范围，保留新组字。空范围随后增长的对照也通过；但旧组字结束与新组字启动若在同一次编辑中，等到 `OnEndEdit` 才固定范围已经太迟，旧范围会包含新文字。结束回调内请求同步只读会话并固定私有克隆后，同次和分次编辑均能只清除旧文字。不能只给最终字符串补上当前输入期编号。

真实微软日语的固定 A 对照中，结束回调内的 `GetRange`、同步只读请求、读取与私有克隆重力设置均为 `S_OK`，原路径随后提交一个 `a`。这不是退出清理触发的样本，但克隆在回调返回时释放，尚未证明实际输入法中长期保留范围或新旧组字隔离。拼音与小狼毫本轮只交付普通字符，没有组字，不计入该项验证。接口在此路径可用不等于所有输入法和回调条件均保证可用，见 [RequestEditSession](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfcontext-requesteditsession)。

后续真实日语对照用独立 edit-session 对象保留克隆。结束回调内固定边界后，异步只读请求返回 `TF_S_ASYNC`；实际回调确认已离开结束回调，仍以 `S_OK` 读出固定 `a`，原提交随后正常交付。该观察排在原清理请求之前，改变了调度，未验证原清理后、新组字存在时或快速重新聚焦的隔离。

临时宿主的完整代理对缓冲检查通过，尚未覆盖跨输入期来源。独立 Win32 固定字符对照中，注入按键的 `ExtraInfo` 标记未传到生成的 `WM_CHAR`，消息时间也不同；不能靠这两个字段恢复原输入期。TSF 提交和 `WM_CHAR` 必须分别证明来源，再贯穿 STA、Unity 队列与页面写回。真实快速重新聚焦、关闭与页面重建继续作为实施前验证项，详见[来源与范围对照](./handoffs/26-11-08-1_roadmap-input-defects.md#tsf-迟到提交的来源与范围对照)及[普通字符来源](./handoffs/26-11-08-1_roadmap-input-defects.md#普通字符的消息来源对照)。

窗口身份也不能直接替代输入期。当前 WndProc 忽略消息中的 HWND，统一写到静态当前窗口；TSF 上下文又绑定固定 HWND，提交回调读取共享文本存储。轮换窗口还涉及上下文关联、旧窗口销毁及旧结果何时结束，尚未选用该方案。[AssociateFocus](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfthreadmgr-associatefocus) 的窗口关联规则不能充当异步提交完成契约。

另一项候选边界是同时隔离窗口与文本存储。独立合成 TSF 对照使用未修改的原生库及每个上下文自己的回调 user 标记：旧上下文提交 `a` 时，新上下文仍保留活动组字 `b`，随后 `b` 也按自己的来源提交。它绕开共享文本存储的全范围清理冲突，但尚未验证真实输入法失焦、输入模式保持、快速重新聚焦或回收时机，不能直接写成每输入期新建上下文的决定。

资源对照中，30 个额外初始未激活上下文增加 30 个 USER 对象，进程私有分配增加约 88–100 KiB。它不代表已经使用过的真实输入法上下文成本，清理后的句柄与私有分配也未回到基线。下一步须核对真实激活及默认失焦行为，再确定旧窗口、上下文和写回目标如何释放，不能用固定等待推断收尾。

后续独立真实拼音对照确认，两个上下文同时保持激活时，旧窗口失焦后提交仍携带旧来源标记，新窗口可以开始自己的组字。实际顺序是旧提交先于新组字开始，尚未验证两者重叠。结束回调可先于 `WM_KILLFOCUS` 到达，送键前必须同时核对实际前台与键盘焦点，不能只信资格缓存。日语本轮在焦点切换前自行提交，小狼毫仅产生普通字符，不扩张为两者的失焦组字结论，见[真实焦点对照](./handoffs/26-11-08-1_roadmap-input-defects.md#独立上下文的真实输入与焦点转移)。

多上下文还不能直接沿用原生候选列表监听：它订阅共享线程管理器，未验证候选所属文档。原生销毁也没有异步会话完成屏障。独立原型仅保活到进程退出，不是产品内的回收方案；候选归属、模式保持及安全回收仍须闭合后再选架构。

未采用的短租约方案需要公共接口上的可验证处理契约。当前固定 A 的 `ITfKeystrokeMgr` 探针未接管按键；即使某次接管，也不保证全部异步编辑已完成。现有实验不支持固定等待或重试；已接受的租约只覆盖 composer 聚焦期。

### 生命周期验收

- 独立宿主覆盖微软拼音、微软日语、小狼毫及 US，确认活动档案后再统计。

## 首次前台获取

现有现场已经证明前两次 `Acquire` 失败，第三次在焦点往返后成功。下一轮保持原行为，只记录 `SetForegroundWindow` 返回值、前后 HWND/PID/class、前台变化事件及最后输入 tick，避免窗口标题与输入原文。

被动诊断已构建并通过独立审查。它保留原来的原生调用，在参数和返回值旁插入只读记录。游戏同款 Unity Mono 的隔离检查验证了调用次数、原生返回值和原 `Take` 判定保持不变，也验证了三次真实前台事件回调及同线程解除。尚未部署到 XSOverlay，游戏中的事件覆盖仍待核对。

解释记录时区分三层事实：[原生返回值](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)、即时窗口快照和带事件时间的前台通知。原生 false 但目标已经在前台时，插件的 `Take` 仍可能成功；原生 true 后目标被切走则属于另一类问题。单个 false 不解释拒绝的具体原因。事件缺失只有在钩子有效、未过观察期限且无丢记录时才有参考价值。

[最后输入时间](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo)仅属于当前登录会话，且不保证严格递增。它不能单独证明哪个进程收到最后输入。前台回调记录事件时间和回调时间，窗口 PID/class 是回调时的查询结果，不能当成窗口销毁前的历史身份。

从冷启动依次标记首次请求、用户点击桌面浮窗、再次请求同一输入项。比较系统直接拒绝与其他窗口夺回，确认实际输入项后再判定成功。按来源选择修复点；不通过合成 Alt、切换模式或定时重试获取前台。租约寿命调整不能替代该实验。

## 放行与恢复

页面和插件检查使用 [AGENTS.md](../AGENTS.md#命令) 的现有命令。针对上述边界运行有意义的回归，再检查文档与格式。产品部署时保留原 DLL 哈希和备份，经 Steam 停止 XSOverlay 后替换，恢复时还原备份并重启。

当前游戏未安装浏览器自测控制件。独立宿主临时服务器与子进程已清理。头显休息期间完成桌面验证，需要 VR 的验收集中留到用户下次使用时。
