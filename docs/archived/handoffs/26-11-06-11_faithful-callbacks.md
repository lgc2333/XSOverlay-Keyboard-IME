# 忠实回调：删掉判据（2026-11-06）

接续 [26-11-06-10](./26-11-06-10_mode-by-behavior.md)。上一轮把「插件不切中英」定成 0025，判据读 IMM32。这一轮推翻判据本身：插件不判断中英，只按「输入法是否正在组字」路由按键。代码已提交，控制台探针跑通中英两组，真机尚未验证。

## 现状一句话

判据整条链已删除并提交。中文态回归全对，英文态透传写回成立。VR 验证被一个发现挡住：中英状态按输入上下文各自保存，新上下文一律从英文开始。

## 决定

- [0026](../../adr/0026-faithful-callbacks.md) 取代 [0025](../../adr/0025-respect-ime-mode.md)：插件不读也不写任何输入法模式。组字中所有键归输入法，翻译不出的键名直接丢弃；不在组字时只接管单按且能算出一个非空格字符的键，其余放行给键盘页。输入法原样送出的字符写回后立刻结束会话。
- [0027](../../adr/0027-cancel-composition-on-caret-move.md)：组字期间输入框光标一动就取消组字，取消方式是把 Escape 送进输入法。状态是 `proposed`，两端都还没写。
- 用户拍板的三件事：忠实回调，不替无响应输入法兜底；已提交文本归 Chromium，控制键在非组字时交回页面，不自己实现文本编辑；喂键后的 120 毫秒停顿删掉。

## 为什么

0025 的判据有一个从没验证过的前提：插件能在自己的宿主窗口上拿到输入上下文。拿不到就永不接管，比要修的故障更糟。而判断中英本来只为了回答「这一个键该不该接管」，输入法自己会用回调回答按键的下场，不需要插件替它预判。

## 本轮实现

删除：开闭隔间的 `ImeCompartments`、模式映射 `ImeMode` / `ImeModeMap`、TSF 隔间接口与 `NativeVariant`、`TF_GetThreadMgr`、模式回调与 `iime_get_mode`（含原生薄壳）、`PumpUntil`、`SendInput` 后的 120 毫秒停顿、闸门的第三档。

新增与修正：

- 直通字符写回后立刻结束会话，会话不再停留在「只收提交键」。
- 输入法不持有组字时结束会话，Esc 取消组字后不会挂住会话与前台。
- 组字中翻译不出的键名吞掉，不落到页面去改被组字串占住的输入框。
- 带 Ctrl、Alt 等修饰的键一律放行，只认 Shift。
- 闸门读到过期组字状态时按「组字中」处理：队列里还有未处理的键就算组字中。

两处提交：`f58b41d` 为主改动（154 增 / 518 删），`7dbc39e` 为闸门过期修复。

## 代码审查

按仓库技能跑了两轴审查，两边都提了实料：

- 标准轴：注释重复 ADR 论证（违反 `AGENTS.md`）、0027 状态与代码漂移、修饰键两套匹配语义、裸字符串名单。
- 规格轴：0027 全未落地、`ImeContext` 两处注释仍提模式、删 120 毫秒无依据、未知键名会落回页面。

处理结果：注释瘦身、0027 降为 `proposed`、匹配谓词合并成一个、补回 `WIN` / `META` 并按页面命名习惯说明理由、未知键改吞、120 毫秒删除与闸门新鲜度都写进 0026 的后果。

## 验证（控制台探针）

探针把 `Ime/`、`Takeover/`、`Interop/`、`Input/` 编进控制台程序，喂的是键盘页同款 `PageKey`。临时工程，未入库。

| 场景         | 结果                                                  |
| ------------ | ----------------------------------------------------- |
| `twice`      | 两次都出 `你好`                                       |
| `digit`      | `2` 选第二候选 `👋`                                   |
| `page`       | 翻页后空格提交翻页首候选                              |
| `enter`      | 回车提交原始编码 `nihc`                               |
| `esc`        | 取消后重打仍出 `你好`，会话确实结束                   |
| `back`       | 退格后空格仍出 `你好`                                 |
| `punct`      | 先提交 `你好`，再提交 `，`                            |
| `leftenter`  | 左方向后回车只提交光标前的 `ni`                       |
| `tab`        | Tab 被接管，空格继续组字                              |
| `shift`      | Shift 放行，空格仍提交                                |
| `digitfirst` | 首键 `2` 原样写回并结束会话，随后字母正常组字         |
| `unknown`    | 组字中 F13 被吞，非组字时放行                         |
| `fast 0`     | 四键零间隔，中文态空格提交 `你好`；英文态空格原样写回 |

英文态每字符端到端约 26 毫秒（含控制台打印开销），四个键 80 毫秒。这个量级不足以让人感到迟钝，暂时不需要「键盘页打开期间一直持有前台」。

`fast 0` 最初暴露了闸门读到过期状态：空格被判成非组字而放行，组字没提交。间隔 20 毫秒即正常，说明滞后在 20 毫秒以内。已按上面的「键在途即算组字中」修掉，修后两种模式都正确。

## 重要发现：中英状态按上下文各自保存

宿主窗口每新建一次输入上下文，探针读到的都是 `native=False`，即使上一次运行已经切到中文。在同一个进程里给宿主窗口按一次 Shift，状态从 `0xb30` 变 `0xb31`，随后组字正常。

这意味着：插件不切中英之后，XSOverlay 里每次启动都从英文态开始，VR 里根本打不出中文。以前能用，是因为旧代码每次按键都强行翻隔间。

修法不违反 0026：中英切换是用户的显式动作，插件只把这一次按键转交给输入法。也就是页面上放一个控件，按下时送一次 Shift。`Shift_L` 在非组字时就是切换键，组字时是 `commit_code`。

## 未定

中英控件的形态三选一：候选栏里的自绘「中/英」chip；键盘布局里合成一个中英键（[0012](../../adr/0012-synthesized-modifier-key.md) 的原方案）；两者都做，chip 显示状态、布局键负责按。倾向第一种，它还能顺带裁决 0012 的存废。

## 环境要点

- 原生库的 C ABI 变了（去掉模式回调与 `iime_get_mode`）。部署前必须 `pwsh native/build.ps1`，否则插件与 DLL 对不上。
- XSOverlay 没运行时可以直接部署，不必先去 Steam 停 XSOverlay。
- 探针里要测中文，必须在同一进程内先给宿主窗口按一次 Shift；跨进程切换不会被继承。
