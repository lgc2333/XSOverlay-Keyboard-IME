# 接管能提交了

接续 [26-11-06-1](./26-11-06-1_takeover.md)。这次修掉"按键被吃掉、输入框里什么也没有"，并让组字真正走到写回。

## 根因

XSOverlay 在 `Awake` 之后立即禁用并销毁 BepInEx 的加载器对象。插件的 `Start`、`Update`、`OnApplicationFocus` 从不被调用，`OnDisable` 与 `OnDestroy` 照常触发；旧的 `OnDestroy` 调用 `UnpatchSelf()`，于是所有补丁在启动后被静默撤销。表现为按键毫无反应，连一行日志都不出。

## 做了什么

| 改动         | 内容                                                                                                              |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| 补丁生命周期 | 加载器销毁时不再撤销补丁，只在 `OnApplicationQuit` 撤销；启动时按补丁 owner 校验两个补丁都在                      |
| 帧泵         | 新增 `InputManager.Update` 后缀补丁排空主线程队列，见 [0017](../../adr/0017-frame-pump-patch-point.md)            |
| 组字生命周期 | 会话从第一个被接管的文本键开始，到提交键（空格、回车）结束；每次喂键后把消息泵走，让输入法作答                    |
| 非组字字符   | 输入法没有组字时，字符落进控件文本后立即写回，不再丢字                                                            |
| 提交         | 输入法接走提交键时读提交文本；输入法仍留在组字里时把组字串当 raw 提交                                             |
| 控制键判据   | 只看 UI 元素会丢组字，改为"读到组字串或已收到 UI 元素"，[0016](../../adr/0016-key-interception-point.md) 就地更新 |
| IMM 解码     | 按返回的字节数解码，修掉组字串里的乱码                                                                            |

## 已验证

- 接管与写回端到端成立。日志：`feed Space` → `committed '你好'` → `writeback '你好' -> inserted`。
- 组字串稳定可读：`ni` → `ni h` → `ni hao`，候选 6 个，乱码消失。
- `dotnet build`（含自检变体）、17 项测试、CSharpier、Prettier 全部通过。

## 已知限制

- 组字期间页面不显示组字串与候选，只有日志；这是刻意延后的一项。
- 组字会话期间一直持有前台租约，到提交键才交还。用户中途离开时前台不会自己回来。
- 拒绝日志有 2 秒节流，验证期可能吞掉连续拒绝。
- 回车提交只有代码路径，尚未在 VR 里按过；空格提交已验证。
