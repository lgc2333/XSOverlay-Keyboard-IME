# 回车

> 历史归档（2026-11-10）：保留调查时的事实、方案与待验证项。当前实现以源码、测试、已接受的 [ADR](../../adr/) 和[路线图](../../ROADMAP.md)为准。

归档时补记：首次 Return 请求与模块加载解耦已在源码实现，15 项专项回归通过。完整页面回归 35 项通过，一项浏览器启动超时后单独补跑通过。尚未部署或完成真实 VR 验收；以下保留此前调查与修复建议。

路由规则见 [0047](../../adr/0047-route-page-consumed-return-through-the-host.md)。这里记本轮「按回车没反应」的缺陷与修复状态。

## 缺陷

- 回车路由先加载原页按键模块，成功后才请求宿主。模块地址写成 `/UserInterface/Default/Keyboard/js/keyboard-input.js`，真实键盘页却从 `/apps/UserInterface/Default/Keyboard/Keyboard.html` 加载。现场只读 GET 确认前者返回 404，补上 `/apps` 后返回 200。
- 加载失败后不会请求宿主，已阻止的原事件也不会重放；失败 Promise 被缓存，后续 VR 回车继续失败。回车音效模块使用同一错误地址。
- 浏览器回归服务器也提供无 `/apps` 的地址，掩盖了该缺陷。服务器必须提供真实路径，旧路径与未知模块返回 404。

## 已实现

- 修正 [native-keyboard-input](../../../web/src/native-keyboard-input.ts) 与 [return-feedback](../../../web/src/return-feedback.ts) 的模块地址。
- 修正[测试服务器](../../../web/tests/server.mjs)的映射。
- 保留现有按压、重复、音效、触觉与回车归属；错误后不重放按键。

## 证据

- 现有三条回车浏览器测试通过，但送键是 mock，不覆盖真实宿主往返。
- 按真实路由重跑隔离实验：DOM Enter 的空闲与组字两项通过；pointer 与 touch 四项返回零请求、零发送，并记录 `Return input failed`。只在调查脚本的内存 bundle 中补全地址后，六项全部通过。宿主答复、焦点释放与最终发送仍为模拟边界。
- 被动诊断捕获组字期间与空格提交后的回车：页面收到 Return 的 pointer、touch 按下与抬起，composer 与 document 均有焦点，但没有任何宿主 Return 请求或判定；用户确认两者均无反应。最初捕获的一次回车发生在 composer 失焦、游戏焦点为 false 时，不属于报告的有焦点场景。
- 20:23 监督式 VR 持前台期间，日语已显示 `日本` 和候选，回车仍无宿主请求。实际部署 DLL 的嵌入 bundle 保留旧模块地址；独立四页旧／新 bundle 对照分别得到 404／200 与零／一次 Return bridge，但旧页另有测试 ready API 不兼容，且没有现场网络记录，不能据此认定唯一现场原因。
- 20:50 仅在临时注入脚本内修正该地址，整包哈希与单处替换均通过门槛；随后初始资格未建立，三次切档被临时门禁拦截，没有日语组字或提交。此轮未验收修复，入口拒绝的具体条件也未记录；下次先取得明确资格，再测真实请求与提交。
- 后续单次点击诊断的首个失败项为 `keys-still-down`：页面归属与宿主空闲均通过，计数 1，键号未知；尚未进入获取前台，也没有回车输入。它解释本轮临时入口拒绝，不能追认前轮同因或完成日语验收。
- 23:42 用户手动打开键盘后的复测已取得资格：normal Take 失败，受限一次 Alt 后实际宿主前台与 STA 焦点成立。日语产生 11 次 preedit、13 次候选、零提交，原文包括 `にほんｇ`、`日本g`。32 条 Return pointerdown／touchstart 记录均有页面焦点，但无 `kind=return` 或实际 `ComposerReturnInput.TryAccept` 入口；内存地址修正已供应，仍未通链。唯一中断原因尚未确定，不能再称只差部署地址修复，也不能归为日语不响应已收到的 Return。

## 建议修复接线

当前 `begin()` 先阻止原事件，再等待 `loadNativeKeyboardInput()`；Promise 成功且取消／焦点检查通过后，才经重复控制器调用 `requestReturn()`。加载失败的 Promise 还会被缓存。这个耦合可使被拦截的按下始终不询问宿主，但本轮没有网络及 Promise 阶段记录，不能认定它就是唯一现场原因。安装版控制器 `begin()` 会同步执行首次 send，不依赖动画帧。

建议首次按下直接请求宿主，移除原模块加载对首次判定的前置依赖。原控制器仍管理长按重复和动画；避免控制器启动时重复发送首次请求，每次 repeat 继续询问宿主。仅在宿主答复空闲时交回原页发送，保留失焦、释放与取消规则，加载或反馈失败不触发补发。此为 [0047](../../adr/0047-route-page-consumed-return-through-the-host.md) 下待实现的修复接线，不是已验证结果。

实现时用同一按压身份记录拦截、模块成功／失败、取消原因、bridge 尝试、宿主收到和判定，先在离线回归覆盖模块延迟／失败、释放、失焦、长按与重复答复，再安排真实 VR。停止用零宿主请求反推某个未记录的页面分支。

## 验收

- DOM Enter、pointer、touch 在空闲与组字时共六种路径：空闲恰好走一次原发送，组字恰好请求一次宿主且保持 composer 焦点。
- 真实 VR 页面核对宿主答复、提交、音效、触觉与最终发送，集中安排一次验收。
