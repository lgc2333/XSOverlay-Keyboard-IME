# 首次切换无效：最小端到端方案（待评审）

> 历史归档（2026-11-10）：保留调查时的事实、方案与待验证项。当前实现以源码、测试、已接受的 [ADR](../../adr/) 和[路线图](../../ROADMAP.md)为准。

2026-11-09。机制方案，不授权产品实现。依据 [0050](../../adr/0050-hold-the-host-focus-for-the-composer.md)、[0055](../../adr/0055-use-one-alt-pair-after-a-denied-focus-request.md)、[0057](../../adr/0057-apply-ime-results-to-the-current-composer.md)；首次回点边界已按 [0058](../../adr/0058-allow-refocus-rejection-during-revocation.md) 缩小，并按 [0060](../../adr/0060-create-refocus-requests-when-page-input-arrives.md) 以页面收到操作为界。与[第一项方案](ime-input-repair-plan.md)共用一个 STA 的送键资格，不另建一套租约。

推荐把前台寿命从组字会话拆出：只有新的已授权聚焦入口能获取，持有期间的按键、档案和模式动作只检查资格；失焦先撤销，再异步清页面。四块机制稿已齐备；[撤销确认与重开协议](foreground-refocus-protocol.md)的状态交错与实际输入覆盖仍须验证。

## 1. 明确入口：正常一次，失败后受限一次 Alt

**推荐机制：** 页面、文档实例和聚焦请求具有不可变身份。通过入口授权后，原 STA 记住原前台 HWND/PID/TID，正常请求一次，并分别记录原生 BOOL、实际 foreground 与 STA focus；BOOL 不能代替实际核验。只有确认失败才检查 0055 的 Alt 分支，未知观测不作为追加请求许可：原前台及请求来源未变、宿主与页面仍有效、没有按住键或活动菜单，才插入一批 Alt down/up；仅插入数 2 允许再请求一次。其余结果结束本请求，进入第三块。正常请求不以键／菜单空闲为前提。

**证据：** 原 Unity 隐藏宿主经 Alt 取得实际前台／焦点，原页面拼音首键组字及 Return 提交通过；正常成功也持续持有至 A／退格的对照通过。21:14 拒绝发生在探针的正常请求之前；21 例假 Native 对照支持移除该额外守卫。见[获取记录](foreground-acquire.md)、[入口守卫](foreground-acquire-guards.md)。

**否定走法：** 每键 `Ensure`、等释放后重试、附加 Attach／换线程资格矩阵、插入不足后补键，均不采用。

**风险：** Alt 是全局输入，已由 0055 接受非事务风险。插入数、钩子和键状态快照不提供处理完成或恢复保证；正常请求的返回与实际激活也应分开观察。不把一次观测扩大成以后不可能迟激活。首次打开的焦点生产者未完全识别，不能把 `visible=true` 当授权。

**必要验收：** 正常成功只请求一次、Alt 为零；正常失败且键／菜单不空闲仍先正常一次、Alt 为零；空闲失败最多一批 Alt 和一次附加请求。插入 0／1、来源变化或目标失效均终止；真实现场确认失败后无文字、无后续自动获取。

## 2. 持续租约：原 STA 撤销，旧工作不得重新获取

**推荐机制：** STA 管理空闲／获取中／持有／已撤销状态。成功后保持租约；组字 End、普通字符交付、批次完成、档案切换或修饰键释放均不归还。窗口 focus／activation 变化时核验实际 foreground 与 STA focus，确认失去资格即先撤销，再通知 Unity。按键、档案及模式请求入队时携带资格身份，出队与每个新的外部调用入口复查；旧请求不能被重新标成当前期。

撤销及队列 admission 共用短小状态边界，不持跨线程锁调用 Win32／TSF／页面。回调重入可撤销当前资格，返回后不得继续下一次旧调用；已进入系统的输入不可撤回，不能承诺全局 `SendInput` 与 HWND 原子绑定。未发旧键作废，但已送出的修饰键须沿 [0040](../../adr/0040-modifiers-follow-the-game.md) 完成匹配释放；它是清理，不取得新资格，也不是复位用户全部按键。

**证据：** 原 STA 自然失焦后阻止旧档案请求、真实 VR 拒绝旧 B，失焦后没有再 Take；正常成功后的持续持有及撤销完成后的真实 VR 一次回点已有阳性。原实现仍按动作获取／归还且队列无身份，见[宿主生命周期](host-lifecycle.md)。

**否定走法：** 仅清布尔 active、给积压键换新代次、丢弃全部 keyup、WndProc 等待 DOM、锁住队列跨 `Send`，均不采用。

**风险：** 这些设计不提供跨线程撤销与系统派发的事务。必须记录已入场与尚未发送的区别，不能把调用前检查冒充检查到调用的原子性；实际重入和所有发送入口尚待实现回归。

**必要验收：** 在实际宿主路径把撤销放在出队前、两次原生调用间及回调内；后续旧键／档案／模式动作均不获取、不继续，旧完成回调不释放新队列。修饰键已发／未发分别核对，不能因丢弃旧业务而卡住系统按键。

## 3. 失败、主动失焦、关闭／重载：定向 clear + blur，条件归还

**推荐机制：** 获取失败或资格结束，先作废原生资格；随后向捕获的 WebView／文档／请求发送撤销，不调用“当前页面”快捷入口。页面仅在身份仍匹配时，同一次脚本先清 `focused` 及重建保焦依据、活动显示，再 blur 对应 composer。旧通知不作用于新请求；重复通知无副作用。脚本缺失、页面销毁或答复未知不重放业务操作，原生撤销不依赖 DOM 答复。

`PageUnavailable` 不再只隐藏 ChatBox：替换、关闭和 load-start 同时使旧文档资格失效；同一 IWebView 重载也更新文档身份。新文档须经当前初始化回执才可工作，旧消息与旧回执不能激活它。页面主动 inactive 也携带原请求身份。window 恢复、初始状态与布局重建仅更新状态，不能自行恢复被撤销资格。

结束时仅在宿主仍为实际前台、原窗口身份仍有效时归还一次；用户已选其他窗口就跳过。失败只报告观测，不循环激活。普通失焦交给输入法默认行为，不发 Escape、不强制提交、不用原生开关模拟失焦。组字／候选／提交按 0057 交当前有效且聚焦 composer，否则丢弃；结果与清理完成均不能重新授予送键资格。

**证据：** 正向条件归还与自然切走后跳过归还均有有限实测。现页面 inactive 不 blur、只 blur 后重建又保焦已有反例；局部同步 clear + blur 对照通过。`PageUnavailable` 仅隐藏 ChatBox、同 WebView 不分文档仍是生产缺口。见[接线评审](foreground-acquire-review.md)、[当前结果边界](late-commit.md)。

**否定走法：** 只 blur 不清保焦依据、无目标的全局 blur、旧 inactive 关闭新期、结果写回前临时 `.focus()`、未知答复后重试，以及失焦强制结算均不采用。

**风险：** 页面撤销消息是异步的；请求身份只能保护已知新旧通知，不证明新请求发生时间。初始化、关闭／重载、丢答复与完整清理链尚无产品集成证明；归还返回也不等于任意输入已排空。

**必要验收：** 失败后清显示且失焦，随后的布局重建不复活；旧 clear／inactive 晚于新期时不伤新期；同 WebView 重载拒绝旧消息；关闭时分别覆盖宿主仍前台和用户已切走。三类结果持焦可用、失焦丢弃且不缓存，原生清理由第一项方案完成。

## 4. 已接受的页面边界与重开协议

旧请求在撤销前产生但晚到，与撤销后页面未知新代次时产生的首次新请求，可以具有完全相同的 payload 和主机可见历史。只增加请求 ID／UUID、收件代次或高精度时间不能区分它们。独立 JS marker 已出现安装版 Vuplex 逆序；`focusin.isTrusted`、游戏 focusId、当前 DOM 焦点也不是该先后事实。见[两历史反例](foreground-acquire-review.md#来源过滤的证据和缺口)。

有限输入 timestamp 载体证明过旧拒绝／新接受，但没有完成真实生产者覆盖、真实通知在途和旧 DOM 副作用隔离。直接注入若只执行 focus／合成事件，会丢失原生 caret、拖选和 Tab 行为；完整适配扩展已停止。**目前没有证据支持在这个范围内简单兼得，不等于证明所有实现不可能。**

0058 已接受同步窗口内拒绝新操作、要求用户重新操作，且不保证至多多点一次。0060 进一步接受页面收到明确操作才产生新请求：较早原生输入若到同步完成后才到页面，可以算新操作；撤销前已产生的页面请求及旧送键仍作废。这个例外控制来源追踪成本，不是输入队列排空证明。

最小机制为：原 STA 先关闭资格并递增代次；页面同次清保焦依据和 blur 后确认；主机仅对当前等待代次发开放许可；页面开放后才在实际输入事件中创建不可变请求。许可、状态恢复与自动 focus 不获取。重复 clear／ack／open、重载与旧成功答复均按身份、代次和状态过滤，详见[协议与待验证入口](foreground-refocus-protocol.md)。保留原生编辑，不采用 CDP 或完整 JS 编辑接管。

原生编辑顺序由第一项方案负责，不用本条边界掩盖编辑完成协议的另一缺口。

**必要验收：** 记录原 STA 已撤销、页面通知实际仍在途，交错旧页面请求与真实新操作，不由 fixture 直接供应最新代次。同步窗口可拒绝；开放后拒绝旧页面请求，但接受 0060 允许的新到达原生事件。核对重复通知、旧答复、重载，以及 pointer／touch、Tab／Shift+Tab 和首次打开；保留 caret、拖选和 Tab 的原生对照。省略通知不算真实在途。
