## 输入法模式的实测

单进程内分四轮，每轮先写隔间再逐键输入 `nihc` 加空格，四轮结果：

| 轮次 | 写入值 | 隔间读回 | 行为                           |
| ---- | ------ | -------- | ------------------------------ |
| 1    | 0      | closed   | 组字，提交「你好」             |
| 2    | 0      | closed   | 原样直通，五个字符全是普通文本 |
| 3    | 1      | open     | 组字，提交「你好」             |
| 4    | 1      | open     | 原样直通                       |

同一个值连写两次，模式翻转两次。所以写入隔间 `GUID_COMPARTMENT_KEYBOARD_OPENCLOSE` 是**翻转**，不是设定：无法用它「强制打开」输入法。

这解释了旧实现为什么看起来能用：本机输入法默认英文，每次组字前恰好写一次、结束再写回一次，两次翻转正好把模式推回原处。任何一次写漏或写多，行为就翻车；用户本来在中文时反而会被翻成英文；异常退出没走到还原，模式会一直留在翻转后的状态。

补充实测：

- 合成一次 Shift 能让模式由直通变组字，提交「你好」。但能否切换取决于输入法的键位配置，因此只作降级兜底，不作主路径。
- 宿主报告的模式回调可用：`AlphaNumeric` 表示按键会进组字，`Native` 表示原样直通。每次模式变化都会回调，但**是异步的**：紧接一次切换后的同步读取仍是旧值，必须等回调到达再判定。
- 输入法处于直通模式时，按键会以 `WM_CHAR` 落到宿主窗口。宿主必须自己收集这些字符作为「未组字文本」，这条取代了旧宿主读控件文本的做法。

## 四条新 ADR

- [0022](../adr/0022-ingameime-host.md)：组字宿主改用 IngameIME。组字串、候选、提交、模式全部走回调；插件不再实现任何 TSF 接口，也不再读 IMM。
- [0023](../adr/0023-dynamic-link-shim.md)：以上游仓库作子模块，构建动态库，再套一层自有的 C 薄壳。动态链接是 LGPL 2.1 的要求；薄壳隔离 C++ ABI。
- [0024](../adr/0024-managed-delegate-callbacks.md)：原生回调改用托管委托函数指针。回调里抛异常会以 `STATUS_FATAL_USER_CALLBACK_EXCEPTION` 直接杀进程，因此回调体一律自行捕获。
- [0025](../adr/0025-mode-flip-on-demand.md)：组字前读模式，只在读到直通时翻转一次，写与当前值相反的值，结束不还原。
