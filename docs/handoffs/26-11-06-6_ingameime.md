# 组字提交边界与 IngameIME 选型（2026-11-06）

接续 [26-11-06-5](./26-11-06-5_display-only-bar.md)。这一轮修组字期间回车，随后挖出提交边界的老问题，最后选定换成现成输入法宿主库；按用户要求，本轮的代码改动与新增 ADR 全部撤销，只留这份记录。

## 结论

- 组字期间的回车曾改为「页面截住 → 请插件提交 → 插件喂回车」，实机通过；该改动已撤，实现留在下面「已验证的行为」里，供新宿主方案复用。
- 组字期间按 `\` 等键会把文本写回两次，根因已定位（后备分支重复读提交串），当时加的守卫随本轮改动一起撤销，问题回到未修状态。
- Tab 这类「IME 提交一部分、继续组剩下」的中间态没有模型能表达，未处理。
- 方向定为接入 IngameIME（`IngameIME-Common` 接口 + `IngameIME_Win32` 实现，LGPL 2.1）；实验已通过，集成未开始，新 ADR 等集成时一并写。

## 真机事实（勿重复试）

- `\` 重复写回：一次 `committed '和、'` 后面跟两条 `writeback`。第二条来自 `Send` 的后备分支：编辑框虽已清空，但读提交串会退回 IMM 的结果串，那里还留着上一次提交。
- 组字期间读编辑框文本当「已提交」是错的：Rime 会把组字串本身写进控件文本。本轮做过一次这样的改动，结果每次按键都把编码当文本写回、组字当场结束，已完整回退，别再走这条路。
- 键盘页打开、输入框聚焦时，系统键盘焦点落在渲染键盘页的 Chromium 窗口（类名 `Chrome_WidgetWin_1`），不是 Unity 窗口。所以「借 Unity 自带输入法」这条路作废。

## 已验证的行为（实现已撤，结论保留）

- 回车：组字期间由页面在捕获阶段截住输入框 keydown 与回车内键的 pointerdown，改发一条页面消息请插件提交；插件入队一个回车喂给输入法，页面继续持有焦点、不清空输入框。真机三个回合均成立。
- 同一按压可能被两层拦截各请求一次提交，需按组字去重，否则会喂两次回车：第二次没有组字便落进编辑框变成回车，被读成空格，或再提交一遍候选。

## IngameIME 实验

仓库关系：`IngameIME-Common` 只有接口头，`IngameIME_Win32` 是实现（并把 Common 作为子模块），`IngameIME_Sharp` 是旧的 C++/CLI 封装，Unity 的 Mono 加载不了，对我们无用。

- 曾 fork `IngameIME_Sharp` 并把子模块指到 Win32，随后决定不用它：里面是旧的 C++/CLI 封装，Mono 加载不了，源码也照旧接口写。这个 fork 要删掉（本机 token 缺 `delete_repo` 权限，待授权后执行）。实现库改为把 `IngameIME_Win32`（含 Common）引入本仓库，再在其上盖绑定。
- 构建：MSVC 14.51 + CMake 4.4.4（`uvx --from cmake`），产物 `IngameIME_Static.lib`。新版不需要 ATL；早期为旧仓库写的 ATL 兼容层已作废。
- 探针（临时，未入库；普通 Win32 窗口 + TSF + `uiLess=true` + SendInput 敲 `nihc`）：得到组字开始/更新（含成串与光标）、候选（含选中与列表）、提交串、输入法模式四类回调；按空格提交得到 `你好` 一次。
- `uiLess=false` 时不订阅候选回调（输入法自己画窗）；要自己画候选必须 `uiLess=true`。
- 打字间隔 120ms 时有一次组字提前结束，300ms 连跑两次都稳定。当前插件每个键间隔正好 120ms，属于临界。
