# TSF 消息泵与物理编辑键调查

## 范围与状态

本轮为 0050 的物理输入路由调查，只改临时探针，未改产品代码、部署 DLL 或新增架构决定。既有真实游戏观察只覆盖实体键到宿主，尚无主动路由原型，见[上一轮](./26-11-08-5_vuplex-background-undo.md#物理输入的边界)。

本轮使用独立 x64 Win32 宿主与固定 `A → Left → Backspace → Ctrl+Z`，由 `SendInput` 注入。它不等同于实体键盘、Unity Mono 或真实 Vuplex 往返。探针仅统计并接收字符，没有文本编辑模型。

## 消息泵定义

| 模式       | 取消息与消费顺序                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------- |
| `plain`    | Win32 `GetMessageW`，然后 `TranslateMessage`、`DispatchMessageW`                                         |
| `wrapper`  | `ITfMessagePump::GetMessageW`，然后 `TranslateMessage`、`DispatchMessageW`                               |
| `filtered` | 同 `wrapper` 取消息，先 `TestKeyDown/Up`；测试吃键才调用 `KeyDown/Up`，确认吃键后跳过 Translate/Dispatch |

接口按本机 Windows SDK 10.0.26100.0 的 x64 声明核对：`ITfMessagePump::GetMessageW` 为虚表 slot 6，`ITfKeystrokeMgr` 的四个键方法依次为 slot 6–9。非零 HRESULT、部分注入均使实例无效。

每步等待本轮固定抬键标记被取出，再经过 250 毫秒观察并取快照。该边界只用于有界采样，不是 TSF 完成屏障。标记不用于推断字符或异步提交的来源，静默、队列暂空与退出也不能证明全部结果已到达。

## 首轮独立进程对照

`0.2` 的三个进程各对 US、微软拼音和微软日语发送四组键，共 36 步。日语在 `plain` 中短暂组字后提交固定 `a`；`filtered` 明确记录 A-down 的 `TestKeyDown=true → KeyDown=true`，随后提交 `a`；`wrapper` 在观察区间只出现普通字符。其余编辑键均未处于持续组字状态。

三个进程的源码及二进制哈希相同，但焦点历史不同。`plain` 切日语前曾失焦，`wrapper` 两次取前台失败后经用户点击恢复。档案身份相同不能证明输入法内部状态相同，因此这些差异不能直接归因于消息泵。

三次最终均恢复探针 STA 初始小狼毫档案并以 0 退出，没有部分注入或非零 TSF HRESULT。命令错误单独统计，`invalid=false` 不是无错误证明。

## 同线程交叉对照

`0.3` 在 PID `7852`、托管线程 `2` 内保留同一窗口、上下文和 COM 接口，只切消息泵模式。窗口与上下文持续存在由匹配哈希的源码控制流核对，日志未直接记录其地址。没有读取或修改输入法中英状态。

共发送 84 组键、210 个 INPUT，84 次均检出固定抬键标记，实际检出 105 个带标记的 keyup。发送前均确认实际前台和键盘焦点指向宿主，事件序号 `1–1695` 连续。

| 档案与步骤    | 样本数              | 观察结果                                                                 |
| ------------- | ------------------- | ------------------------------------------------------------------------ |
| 日语 `1–36`   | 每模式三组四键      | 无组字与提交，普通 A、退格和 Ctrl+Z 生成字符消息，Left 无字符            |
| US `37–48`    | 每模式一组四键      | 同上，filtered 的测试均未吃键                                            |
| 拼音 plain    | `49–52/61–64/73–76` | 三组持续组字，各键按下未出现在探针取消息及窗口观察点，15 个抬起仍到达    |
| 拼音 filtered | `53–56/69–72/77–80` | 三组持续组字，15 个按下全部 Test 与 Key 吃键，15 个抬起测试全部不吃键    |
| 拼音 wrapper  | `57–60/65–68/81–84` | 三组没有组字，各组产生普通 A、退格和 Ctrl+Z 字符消息，按下和抬起均到窗口 |

拼音第一次四键后仍在组字，切泵保护返回 `composition-active`，原连续计划随即停止。之后每组之间通过真实 gate 窗口失焦结束输入期，确认结束后才重新聚焦与切泵。不能把九组写成没有失焦的连续交叉。

六个组字组在 gate 取得前台和焦点后都提交一个固定 `a`；提交时宿主已没有前台或键盘焦点。探针没有发送 Escape、强制提交或停用上下文。它再次验证了拼音本次默认失焦结果，但未接到真实页面。

本次只有上述一条命令错误，没有部分注入、非零 TSF HRESULT、回调或窗口异常。最终恢复探针 STA 初始小狼毫，待取固定抬键数为 0，进程退出码为 0。该恢复只核验探针线程档案，不证明外部应用档案、原前台或原生对象回收。

## 可保留的结论

- 显式 TSF 测试与喂键在真实拼音持续组字中确实可以消费键；此前固定 A 的 `eaten=false` 不能代表所有直接接口路径无效。
- 普通取消息路径也能在窗口过程之前产生组字结果。探针看不到按下只说明观察点未见，不能解释底层确切消费路径。
- 组字按下被消费、对应抬起放行已经复现。页面路由必须核验按下与抬起归属，不能逐条转发所有放行消息。
- 本轮日语没有持续组字；用户模式、日语编辑语义和实体键行为仍未验证。
- 取消息和单键的 `eaten` 结果不能缩短 0050 的聚焦期租约，也不提供异步提交完成契约。

## 下一步

优先验证显式过滤后，把未消费的编辑键交给原页面编辑通道，普通字符只从字符结果交付。独立核对按下与抬起、修饰键、重复、失焦、字符去重和原生撤销。先完成临时原型，再在真实 Vuplex 与实体键上验收。

现有游戏观察器只有 start、stop、snapshot，后台写回工具只有固定写入与撤销实验，二者尚未连接。路由可用也不解决迟到提交的来源、输入模式保持或旧上下文回收，这些边界继续按[落地方案](archived-notes/late-commit.md)调查。
