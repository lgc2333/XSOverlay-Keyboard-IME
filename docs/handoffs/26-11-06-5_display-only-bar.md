# 候选栏改为只显示

接续 [26-11-06-4](./26-11-06-4_candidate-bar.md)。上一轮把候选栏与组字串做上屏，这一轮按用户决定把候选栏收成只显示，并加上字号对齐。

## 结论

- 候选栏只显示：候选、当前高亮、输入法名字。不响应点击。
- 选候选与翻页用键盘页自己的数字键与 PageUp/PageDown，经接管路径送进组字宿主，见 [0018](../adr/0018-candidate-bar-display-only.md)。
- 0018 用 `amends` 指向 [0010](../adr/0010-candidate-by-keys.md)；0010 只在开头加 `amended_by: ['0018']`，正文没动。
- 候选栏所有文字的字号与字族改成和 composer 输入框一致（20px，Roboto Flex）。

## 做了什么

| 改动     | 内容                                                                                                      |
| -------- | --------------------------------------------------------------------------------------------------------- |
| 删点选   | 页面点击处理、翻页键、页到插件的动作协议、插件合成按键与输入法判族全部删除，净减 575 行                   |
| 页面消息 | 页面只回报一条"脚本已就绪"，插件只写日志                                                                  |
| 字号对齐 | 候选栏由 15px 改为 20px，字族与输入框相同；序号不再单独缩小                                               |
| 文档     | 新增 0018；改 [CONTEXT.md](../../CONTEXT.md) 的候选栏定义；改 [AGENTS.md](../../AGENTS.md) 的目录职责说明 |

## 真机反馈与修复

第一次真机验证发现三处问题，已修：

| 问题                     | 真因                                                                   | 修法                                                                                                   |
| ------------------------ | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 候选从不显示             | TSF 的候选元素编号就是 0，被当成"没有元素"，于是从不去读候选           | 另用标志位记录"元素已打开"，编号 0 也照常读取                                                          |
| 组字串只在输入框空时可见 | 组字串写在 `placeholder`，浏览器只在输入框为空时显示占位文字           | 组字串临时拼进输入框已有文字的光标处，提交后还原，见 [0019](../adr/0019-inline-preedit-in-composer.md) |
| 键盘打开时没有候选栏     | 脚本在第一次击键才注入，候选栏随后出现，键盘高度突变                   | 挂在游戏的"设置键盘可见性"上注入，另加启动尝试，见 [0020](../adr/0020-inject-page-on-keyboard-open.md) |
| 日志反复报"页面没响应"   | `showComposition` 返回 `undefined`，被判成缺脚本，于是每次调用都重注入 | 页面函数经包装调用，返回 `ok` 或哨兵值                                                                 |

真机日志已确认：启动后立刻出现 `page message: xso-keyboard-ime ready`，说明键盘页在用户按键前就注入了。

第二轮真机验证全部成立：`candidates count=6 sel=0` 每拍都有、输入框里编码带青色下划线、`committed '朋友们'` 后 `writeback ... -> inserted`、没有 `did not reach` 或 `error:`。

## 已验证

- 离线渲染台读 DOM（组字串内联后）：已有文字时组字串拼在其后，`value="晚上好nihc"`、光标在编码末尾、发送键被压住、候选 5 个；清空后 `value` 还原为 `晚上好`、光标回到原处、候选归零。
- 页面重建后再读：候选栏与组字串都自动回来（渲染台曾验证到 `placeholder` 方案，内联方案已用同一断言改写）。
- 字号与输入框一致，截图与定稿对照无差异。
- `dotnet build`（含自检变体）、19 项测试、CSharpier、Prettier、`pnpm --dir web typecheck`、`lint`、`build` 全部通过。
- 测试数从 49 降到 19：点选与判族的 30 项随功能一起删除。
- 真机启动一次：插件加载、补丁生效、帧泵就位，并从 `ITfInputProcessorProfiles` 读到输入法名 `小狼毫`。

## 未验证与已知限制

- 用键盘数字键选候选没有实测：日志里没有任何数字键的 `feed`。
- VR 里按回车提交只在代码路径上成立，实机只验了空格提交。
- 组字期间插件会取走前台，游戏窗口因此失去激活态；用户观察到输入框的激活描边在此刻变化。若要避免，需要改租约策略。
- 输入法名取当前语言的默认配置，同一语言装了多个输入法时可能不准；见 [0009](../adr/0009-profile-scope.md)。
- 候选栏不在键盘页的射线白名单里，拿不到悬停高亮；栏不可点，没有影响。
- 组字会话期间仍一直持有前台租约，到提交键才交还（旧限制）。
- 候选栏没有输入法下拉，中英键尚未合成进布局。
