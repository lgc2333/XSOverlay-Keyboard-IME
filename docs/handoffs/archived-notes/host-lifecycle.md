# 宿主前台租约

> 历史归档（2026-11-10）：保留调查时的事实、方案与待验证项。当前实现以源码、测试、已接受的 [ADR](../../adr/) 和[路线图](../../ROADMAP.md)为准。

前台安全与失焦收尾见 [0050](../../adr/0050-hold-the-host-focus-for-the-composer.md)，结果按 [0057](../../adr/0057-apply-ime-results-to-the-current-composer.md) 处理，不再保留原目标追溯要求。组字宿主与写回见 [0022](../../adr/0022-ingameime-host.md)、[0008](../../adr/0008-inserttext-writeback.md)。本笔记只记现状、证据与待验证项。

## 现状

- 生产代码仍按单次组字会话结束并归还前台：`CompositionSession.End` → `ForegroundLease.Restore`，送键后只排空键消息。
- `HostWindow.Collect` 只追加 `WM_CHAR`，唯一消费者是送键路径内的 `WriteThroughTyped`。两条机制都未实现：字符到达不通知会话，前台随按键归还。
- 待实现：`WM_CHAR` 到达即交付完整文本（不拆代理对、不等下一次送键）；迟到提交独立交付（[0032](../../adr/0032-deliver-a-late-commit.md)）；组字结束、按键批次结束与修饰键释放都不结束租约。

## 证据：过早归还前台

- 独立宿主（.NET 10，复用生产宿主、会话、送键与档案源码，加载同哈希原生库）每次送一个 A：原样归还时拼音、日语各两次无字符无组字；仅抑制归还时拼音两次开始长度 1 的组字，日语收到一个普通字符；小狼毫原样正常交付。前台获取与 `SendInput` 失败计数为零。
- 结果驱动对照（取消「仅因 `!Composing` 就 End」，字符到达即交付）：拼音 `send-entry → send-return → preedit(0→1)`，续送 Return 被接管并提交；日语 `char-arrival → delivered(1) → session-end`。原样路径仍无输出。该对照未覆盖吃键无输出、异步取消、多字符与代理对，同步 trace 也可能影响时序。
- VR Shift 保持宿主前台后，两款微软输入法都能把文本送进 VR 输入框，说明服务能连上该上下文。
- 原 Unity STA 新增首键阳性：正常获取被拒后，临时 Alt 资格对照使原宿主取得前台；原页面切到拼音，原送键入口的 A 产生组字，Return 提交，随后恢复档案与原前台。该对照未补丁修改 `End/Restore`，档案获取时宿主已经在前台，原 Restore 仍返回宿主。它补充提权游戏内首键证据，但不是 0050 完整焦点期、日语或自然失焦验收。
- 监督式真实 VR 单期对照仅抑制已取得资格的原租约 Restore，保留原消息泵、后端与写回：记录 12 次抑制，中文提交 `你好`、`世界【` 时原宿主均持前台与键盘焦点；日语出现 `にほん`、`日本` 及候选，却无回车请求或提交，见[回车](return-key.md#证据)。42 次组字、2 次提交、42 次候选回调无丢记录；布局重建后页面快照为 `你好世界`、`sameNode=false`，不能把原生提交等同最终页面文本。随后复测未取得初始资格，三次切档被临时门禁拦截，不能记为输入法激活失败；两轮均已停机恢复。该对照未闭合物理输入、默认失焦或来源寿命。

## 证据：游戏内被动诊断

- 无输入段：前台、焦点与 `SendInput` 都成功，但宿主无键消息、无字符、无组字或提交回调。低级按键观察确认注入的 Down/Up 已到达（六对，回调时前台为宿主，下游返回 0）；断点在低级入口之后、宿主队列与文本回调之前，更早的挂钩或其他 TSF 处理未排除。
- 把送键后排空从键消息扩到全部已排队消息（512 条上限，无等待、重试或计时器），两款微软输入法仍无输入、`Collect` 仍空，小狼毫正常。队列暂空不等于异步 TSF 已完成。
- 迟到普通字符已有真机证据：日语缓冲 1→8，约七秒后取消 Shift 才由 `TakeTyped` 取出；另一段单个字符同样等到取消。
- 直接 TSF 固定 A：早期 `TestKeyDown/Up` 为 `S_OK`、`eaten=false`；后续同线程同上下文在真实拼音组字中取得 `TestKeyDown=true → KeyDown=true`。能消费键，但单键消费不是完成契约。
- 组字宿主吞掉全部 `WM_APP` 及以上窗口消息；尚未证明输入法依赖它们。
- 桌面键盘页能送 A 到真实 `InputManager.HandleKeypress`，但 `hasFocus=False`，未进插件宿主。

## 证据：物理输入

- 安装版 Vuplex：`NativeKeyboardListener` 读 Unity `Input.inputString`/`GetKeyDown`，`KeyboardManager` 转发到自己的焦点 WebView；与 XSOverlay 内部的 `KeyboardFocus` 不是同一焦点。
- 安装版没有公开的原始 `MSG`→JS key 转换器。`InputManager.MapWebKey` 是私有的 18 项命名键表，字母依赖页面 `webValue`；`NativeKeyboardListener` 则轮询 Unity，按当前修饰态生成事件，并自行定时重复。它们不能直接补齐宿主消息转换，现有固定路由保存 down 修饰态也不同于该监听器；Ctrl+A/C/V、重复、提前释放修饰键、AltGr 与系统键仍须分别验收。
- 真实 US 档案、空 composer、宿主持前台时，实体 `A → Backspace → Left → Ctrl+Z` 的按下、抬起与 `WM_CHAR` 都只到隐藏宿主，Vuplex 监听与 WebView 送键均未记录；期间 `FrameCount`/`ListenerUpdates` 持续增长。阳性对照经原游戏 `SendKeyboardEvent` 发一次 Backspace，实际 WebView 的 down/up 各记一次。
- 独立 Win32 消息泵对照（84 组四键）：真实拼音在显式过滤泵中 15 个按下全被 `Test → Key` 吃掉、15 个抬起放行；普通取消息泵也组字但看不到按下；只包装取消息的泵产生普通字符。日语、US 与编辑键本轮无持续组字。
- 结论：只有显式过滤能确定按下与抬起的归属；下一步验证把未消费的编辑键交回页面编辑通道、普通字符只从字符结果交付。
- 固定四键原型最初因前台获取失败而未调用 US 档案激活。后续临时显示原宿主，并保存、恢复标题、矩形与扩展样式；控制工具点击后，实际前台为宿主，原页面菜单成功切到 US。路由首次启动成功，`Acquired=true`、`Invalid=false`、`routePumpDepth=1`，3,153 帧内观察与 Vuplex listener 持续更新。
- 控制工具提示目标权限较高；发出的 A 没有宿主或页面事件，不能记作按键转交成功。路由已停止，档案、窗口设置与原诊断 DLL 均恢复；实体四键仍待验证。原型直接把 A 送入 WebView，并丢弃 `WM_CHAR`，只能验证编辑通道；嵌套泵与固定四键不能直接用于产品。
- 同进程固定合成对照已通过：原宿主 STA 的 `SendInput` 完整插入 `A → Backspace → Ctrl+Z → Left`，真实 TSF 过滤均放行，WebView 与页面各收到四对 down/up。页面长度依次 `0→1→0→1→1`，最后选区 `1→0`；仅有一次 `insertText`、`deleteContentBackward` 与 `historyUndo`，没有重复编辑。4,849 帧内宿主持前台、listener 同步增长、无丢记录或无效标记。它验证固定编辑通道，不替代实体输入、普通字符结果或真实 IME 共存。
- 安装版 Vuplex 的分立按键 API 只有 `KeyDown/KeyUp(string, KeyModifier)`，没有禁止文字默认插入的参数。固定 US 对照现已保留 A down/up、阻止默认插入，再将实际宿主 `WM_CHAR U+0061` 写回：捕获、写回与页面插入计数各为 1。逐步确认后，退格、Ctrl+Z 与左移符合预期；7,477 帧无丢记录或无效标记，停止后 fixture 与结果路由均已清除。它未覆盖连续快速输入排序、真实 TIP、实体输入或通用字符分类。
- 八个独立 Chromium 对照另覆盖 Ctrl+A、重复、提前释放 Ctrl、Shift+A 与另一 input；结果来源由实验给定。Ctrl+C/V、完整布局与这些扩展项的真实 Vuplex 行为仍未验收。
- 连续排序已有游戏内反例：一次 `SendInput` 完整插入 A↓↑、退格↓↑，Unity 先提交实际字符脚本，再调用退格；页面却先对空框执行退格，之后才插入 A，最终残留一个字。字符捕获、写回与插入各一次，1,395 帧无丢记录或无效标记。相同批次改走原生默认编辑，先插入再删除，最终为空。该反例来自插件候选混用两种交付路径，不能归为输入法结果或推广为所有调用乱序。
- Unity FIFO 只保证调用顺序，[Vuplex 按键](https://developer.vuplex.com/webview/IWithKeyDownAndUp)与[脚本 API](https://developer.vuplex.com/webview/IWebView#ExecuteJavaScript)未给出共同执行队列。下一对照须以实际字符执行完成约束后续编辑，并单独验证反向顺序、停止与替换；字符回调不能直接充当所有原生按键默认动作的完成标记。
- 字符完成队列已有固定游戏阳性：同一 A＋退格批次 `4/4` 插入，实际字符答复回到 Unity 后才提交后续 up/down；页面先插入一个 A，再删除，最终空框、选区 `[0,0]`。捕获、写回与插入各一次，1,437 帧无丢记录或无效标记；停止后队列关闭、fixture 撤下。队列本体 16 项、source-link 集成 31 项另已通过。该结果只闭合字符先于编辑的固定反例。
- 反向空框退格＋A 已完成三组游戏对照：原生默认、仅字符完成队列、编辑与字符双完成队列均 `4/4` 插入，最终一个 A、选区 `[1,1]`。双队列记录一次页面 keyup 答复回到 Unity，随后才提交 A 与实际字符；捕获、写回、插入各一次，1,445 帧无丢记录或无效标记。它验证固定答复通路可用，但仅字符队列也通过，尚未证明编辑答复必要；空退格没有实际删除，不能推广到非空编辑、快捷键或输入法。三组停止后 fixture、队列、档案与窗口均恢复，原诊断 DLL 已还原。
- 六页 Chromium 对照中，退格／撤销默认编辑与左移已在 keyup 时可见，但选区通知及条件后注册监听器仍可随后改变状态；keyup 与其 microtask 均不是通用完成边界。
- 安装版键盘模块及直接依赖未发现退格、左移或 Ctrl+Z 的专用处理，也无 keyup／beforeinput／选区监听；输入框仅在 Enter keydown 发送，input 回调更新工具栏。前述合成后置 keyup 改值没有对应的安装版处理器。语音恢复另会排帧重设选区，插件组字观察器也可能在稍后通知时取消；故空闲输入框的 keyup 可用于下一次固定反向对照，仍不是整页完成契约。
- 直接编译未修改路由源码的离线对照通过 11 项：down/up 归属、Ctrl 修饰、排队后撤销、目标替换后只向原页面释放一次、disposed 页面不重定向，以及 repeat／Shift／orphan up 拒绝。该对照没有窗口或真实 Vuplex，不能替代成功的游戏内路由样本。

## 已知缺口

- `TryAcceptKey`/`DrainStrokes` 不按 composer 活动资格拦旧队列；`Ensure` 可能重新获取前台。
- 直接编译完整 `ImeHost` 的八组离线对照确认：同目标失焦后重新聚焦，原队列仍发送旧 `a`；复制的资格候选只发送新 `b`，重入撤销也能阻止下一条旧键，pending 均归零。会话与结果为 mock，候选跨 `Send` 持锁，真实跨线程行为及撤销后的修饰键释放尚未验证，不作为产品实现。
- 后续有限对照确认，跨 `Send` 持锁会挡住另一线程撤销，统一资格检查也会丢弃已送出修饰键的匹配 up。七组派生对照移除该锁，并将匹配 up 送回原会话一次，包含目标替换；但在检查与调用之间撤销，旧 `a` 仍可在 false 返回后开始 `Send`。pending 归零不代表边界正确；这些是假会话反例，尚未证明原 STA 与真实按键收尾，不能把派生候选用作产品实现。
- 真实线程路径确认：页面 false 写入 volatile 标志后异步投递，送键循环不读它，原窗口也没有原生失焦撤销分支。独立隐藏 STA 直接运行未修改的窗口投递和消息泵，四种受控次序的 13 项检查通过：Post 返回早于撤销处理；键过滤泵即使取出零键，也能先重入处理合成撤销，返回后须复核才能挡住后续模拟发送。该实验没有真实失焦或输入注入，不能据此保证最终检查与 `SendInput` 原子绑定；请求发布、STA 已撤销与已提交输入须分别验收。
- 当前焦点丢弃尚未完整实现：提交会拒绝失焦写入，但组字仍可缓存并在 `Attach` 重放，候选也能在无焦点时渲染并留到 refocus。两组托管与四页完整脚本对照只证明受控分支；旧送键撤销与真实往返仍待验证，见 [late-commit](late-commit.md#当前焦点丢弃缺口)。
- 游戏 `focusId` 也不能直接补该身份：脚本聚焦与布局重建会生成新 ID，同 overlay 重复请求又按 0021 保留旧 grant；ID 不是明确用户动作的凭据，见[首次前台获取](foreground-acquire.md)。
- 页面失焦经 60 毫秒检查调用 `RequestCancel` 并最终发送 Escape；失焦与编辑取消须分开，保留默认窗口处理。
- 真实迟到提交、物理编辑键、Ctrl+A/C/V 去重、Vuplex 双路输入待验证。

## 落地边界与未决实现

- 生命周期按 0050：独立管理前台租约；组字结束只结束组字。获取失败撤销 composer 焦点，真实失焦立即撤销旧队列资格，发送前核对实际前台与键盘焦点。
- 消息泵在原 STA 正常循环内过滤 TSF；每条消息最多调用一次消费链，未消费编辑键送捕获的 WebView，按下与抬起保留同一归属。普通文字只走宿主结果，页面不要求普通字符原生 down/up，见 [0054](../../adr/0054-write-ordinary-text-through-host-results.md)；嵌套试验泵不作为产品结构。
- 0057 取消原目标结果追溯，不替原生清理选择实现。异步请求的持有对象、范围读写与资源释放仍须安全，不能由「不显示结果」推导可直接销毁宿主。
- 写回继续用原生撤销链支持的 `insertText`，按当前有效聚焦的 composer 及其当前选区处理；否则丢弃且不补发。接受重新聚焦后旧结果混入，结果不能重新授予送键资格。
- 当前结果规则、普通文字路由与[独立组字标签](../../adr/0056-show-preedit-in-a-composer-tab.md)已接受；[0059](../../adr/0059-use-one-transitory-document-for-ime-results.md) 已选择单 STA／单宿主／单 transitory 文档，焦点协议和安全收尾仍须接线验证。证据见[上下文隔离](context-isolation.md)与[迟到提交](late-commit.md)，本轮未开始产品实现。

## 验收

- 覆盖拼音、日语、小狼毫与 US，先确认真实活动档案再统计。
- 用户自行选中英状态；查普通字符、组字、分段转换、提交与取消。
- 查异步无输出、连续输入、多字符，代理对不拆分、不重复交付。
- 真实桌面失焦分别复现小狼毫与拼音，保留输入法默认行为且不发 Escape；页面无有效焦点时不显示或写回，不在重新聚焦后补发已丢弃结果。
- 查粘滞与保持修饰键、组字中切输入项、页面重建、失焦与关闭，无残留按住键、不抢回新窗口。
- 最后在提权 Unity Mono 的真实 VR 页面重测。
