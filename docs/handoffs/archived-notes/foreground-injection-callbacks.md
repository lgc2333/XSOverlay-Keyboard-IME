# 注入操作与同步回调

> 历史归档（2026-11-10）：保留调查时的事实、方案与待验证项。当前实现以源码、测试、已接受的 [ADR](../../adr/) 和[路线图](../../ROADMAP.md)为准。

2026-11-09。临时候选的条件性实验，不是已发现的生产缺陷，不改变[注入方向](foreground-direct-injection.md)或编辑责任。

`focus()`会同步执行页面focus监听器；现安装speech监听器调用API，写pending焦点并发送请求。插件的[focusin监听](../../../web/src/composer-focus.ts)也同步更新局部状态和图标。因此“同一次JS调用”不能直接解释成没有业务回调的事务。

## 刻意允许再入的反例

两版headless Chromium（137.0.7151.119／158.0.8127.18）各6例。安装编辑模块不变，另加回调在focus/focusout中直接再次调用临时操作入口；来源token为harness供应，不是真实原生登记。

| 条件                          | 实际结果，两版相同                                    |
| ----------------------------- | ----------------------------------------------------- |
| focus内已接受新动作2、选7/7   | 外层旧动作1改回2/2，owner/gesture1但highest2，上报2→1 |
| Tab focus内已接受新动作2      | 外层改为0/8与owner1，上报2→1                          |
| 旧clear的focusout内新建owner2 | 旧clear返回后又将owner清为null                        |

普通begin/end/clear及更旧的嵌套动作拒绝各通过；begin尚未建gesture时的cancel返回false，仍继续上报，这是未支持的新候选要求。整体仍不通过，结果未调绿；19个安装文件hash不变，页面／请求错误0。该实验没有连接Unity、STA、真正撤销或安装CEF。

## 不扩大结论

已查实际回调确有同步局部写入，但尚未找到它们同步再次进入候选操作、清宿主owner或取消组字的路径。现重建由MutationObserver处理；收到后续Unity消息也不等于在同一JS栈再入。不能把人为回调当作真实用户动作或生产竞态。

入口检查不能证明再入安全。若未来接线允许再入，须验证回调返回后的动作／owner仍有效；若能排除该再入，就无需因本反例增加对应机制，其他来源／撤销检查仍然需要。先确定可达合同，不因此先给产品增加队列或取消机制。它与[拖选／滚动缺口](foreground-injection-spike.md)是独立问题，均未被局部选区匹配解决。
