# 撤销确认与重新开放协议

> 历史归档（2026-11-10）：保留调查时的事实、方案与待验证项。当前实现以源码、测试、已接受的 [ADR](../../adr/) 和[路线图](../../ROADMAP.md)为准。

2026-11-09。依据用户接受的 [0060](../../adr/0060-create-refocus-requests-when-page-input-arrives.md)，以页面收到操作为界；[0058](../../adr/0058-allow-refocus-rejection-during-revocation.md) 允许同步期间拒绝新操作。以下是待接线验证的最小机制，不是已实现或通过真实 Vuplex 往返的保证。

## 身份与往返

每条消息固定 WebView、文档实例、撤销代次与请求号。文档初始化绑定当前加载代次；同一 WebView 重载也换身份。身份在页面事件入口捕获，定时任务、Unity 队列和 STA 出队均不得改成当前值。

| 阶段   | 原 STA／主机                                                                                     | 页面                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| 撤销   | 先关闭 admission，递增撤销代次，废除旧资格；发送定向撤销。已撤销期的重复失焦不重复递增。         | 尚未收到通知时发出的旧代次请求仍会被拒绝。                                                 |
| 清理   | 保持关闭，不依赖页面才能停止旧工作。                                                             | 接受较新撤销，同一次脚本关闭请求入口、清保焦依据和活动显示、blur；完成后答复该代次已清理。 |
| 确认   | 仅在文档与当前代次相符、仍处于等待清理状态时接受答复，发送该代次的开放许可。                     | 不因答复发出就恢复入口，不重放同步期间的操作。                                             |
| 开放   | 等待新的明确请求；许可本身不调用 Take。                                                          | 仅接受当前已清理代次的许可；开放不 focus，不从当前 activeElement 补造请求。                |
| 新请求 | 只接受当前已开放代次的一个新请求，记录请求已消费后执行正常／受限 Alt 获取；重复请求不重复 Take。 | 在实际输入事件中固定身份，进入等待答复；保留浏览器默认动作，不合成编辑。                   |

清理回执证明指定页面清理已执行，不证明原生输入队列已空。开放后才到页面的旧原生输入按 0060 可以产生新请求；旧页面请求即使随后到达，仍携带旧代次，不能取得资格。

接收条件必须同时检查身份、代次和状态：主机仅在“等待该代次清理”接受清理回执；页面仅在“该代次已清理且尚未开放”接受开放许可；主机仅在“当前代次开放且请求未消费”接受请求。相同代次的重复 open 不能把等待获取答复／持有状态改回开放。初始化从关闭开始，旧文档初始化与清理回执不互认，不能覆盖较新撤销。

## 页面授权入口

- `focusin`、window focus、visibility、初始状态和节点重建只报告状态，不获取资格。`isTrusted` 的 focus 事件也不能替代明确输入事件。
- 输入入口排除脚本 `dispatchEvent`，只观察真实到达页面的 pointer／key 事件；事件可信标志不证明更早的硬件来源，不能恢复 0060 已放弃的物理时间承诺。
- 指针／触摸拟只在实际命中 composer 的 `pointerdown` 建立请求，不再从兼容 mouse／click 重复建请求。必须确认安装版输入路径覆盖该事件；不以模拟事件补齐。
- Tab 拟在页面观察到的配对释放时检查实际目标：down 在当前开放代次被记录，up 仍属于该代次、实际目标与 activeElement 均为 composer 才建立请求。跨撤销的配对作废；不把 keydown 的旧 target 当作导航终点，不把后续任意 focusin 归给 Tab。[UI Events](https://www.w3.org/TR/uievents/#event-type-keyup) 定义 keyup 的目标为处理释放事件时的聚焦元素，而不是对默认导航结果的承诺。该候选须验证安装版与原生 Tab／Shift+Tab 对照，不能先承诺完整覆盖。
- 同一明确操作只建一个请求；请求待答时的新操作不替代它，持有期内的编辑也不再 Take。首次打开的授权生产者仍须接线核实，`visible=true` 不等于授权，不能悄悄改成一律额外点击。

## 重排、重复与失败

旧文档、低代次、旧请求答复均忽略。相同撤销的重复通知只能重述已有清理结果，不再次 blur 已开放的新请求；重复清理回执不能把持有状态降回开放。较新撤销优先，旧开放许可和旧获取成功答复不得复活资格。页面失活消息也固定原请求，不能关闭另一期。

页面取消等待中的请求后，本地入口保持关闭；不自行生成下一请求。原生收到当前开放代次的取消，即使尚未收到该请求，也先关闭并撤销该代次，再走清理确认；后到原请求不能取得资格。若已获取中／持有，只接受匹配原请求的取消；旧代次 inactive 不变更新期，也不产生新开放许可。一个开放代次最多消费一个聚焦请求，避免同代次取消与新请求复用。

清理或初始化答复缺失时保持关闭并报告不可用；不按超时开放、不自动重试获取，也不把原操作重新标为新请求。关闭、load-start 与 WebView 替换立即使旧身份失效，旧注入／初始化回执也不能绑定新文档。文档初始化可以重建接口，不能重放业务操作。

获取中发生失焦或回调重入时，返回后重新检查资格；旧获取不得继续 Alt、送键或确认持有。已进入系统的调用仍不可撤回，沿用[四块方案](foreground-repair-plan.md)的非事务边界与已送修饰键清理责任。

## 最小验证

先用有界交错核对：旧请求晚于清理与开放、开放早于较新撤销到页面、重复 clear 晚于新持有、旧成功答复、同 WebView 重载和缺答复。单独检查 0060 例外：同步后新收到的原生事件可被接受，不能误记为旧请求过滤失败。

再接实际页面往返与原 STA，真实暂停撤销通知并交错新旧请求，不由夹具直接供应最新代次。覆盖 pointer／touch、Tab／Shift+Tab、首次打开、脚本自动 focus 和重建；比较选区、拖选与 undo。协议不接管编辑，也不解决第一项的编辑完成候选。模型、页面局部对照与完整产品／VR验收分别记账，不再重复 Alt 成功矩阵。

本轮有限核对：14 个抽象协议轨迹与 2 个故障控制，共 58 条断言通过，包含取消先于请求、旧 inactive 晚于新持有。初版模型未充分断言状态与副作用，已废弃其完整覆盖结论。另一次 headless Chromium 158 页面观察 8 场景中 7 个通过：Tab／Shift+Tab 的 keyup 指向当前 composer，阻止 Tab、跨代次和脚本 focus 未获准，mouse／touch 各建一次请求。第 8 项没有先建立“已聚焦”前提，保留为夹具失败；未重跑。脚本 focus 的 focusin 仍为 trusted，不能据其授权。以上不是安装 CEF 137、实际 Vuplex 桥或产品验收，也没有测完编辑行为。
