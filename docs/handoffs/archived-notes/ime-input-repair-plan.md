# 微软输入修复：最小方案初稿

> 历史归档（2026-11-10）：保留调查时的事实、方案与待验证项。当前实现以源码、测试、已接受的 [ADR](../../adr/) 和[路线图](../../ROADMAP.md)为准。

本稿是待实现验证的机制方案，不授权产品实现。焦点同步边界、原生后端与新操作起点的取舍已接受，分别见 [0058](../../adr/0058-allow-refocus-rejection-during-revocation.md)、[0059](../../adr/0059-use-one-transitory-document-for-ime-results.md)、[0060](../../adr/0060-create-refocus-requests-when-page-input-arrives.md)；其余约束为 [0050](../../adr/0050-hold-the-host-focus-for-the-composer.md)、[0054](../../adr/0054-write-ordinary-text-through-host-results.md)、[0055](../../adr/0055-use-one-alt-pair-after-a-denied-focus-request.md)、[0056](../../adr/0056-show-preedit-in-a-composer-tab.md)、[0057](../../adr/0057-apply-ime-results-to-the-current-composer.md)。

只处理以下四块。原目标追溯、后台保全、历史锚点和完整 JavaScript 编辑接管保持停止。安全重开按已接受的页面事件边界接撤销确认协议；编辑完成采用下述具体候选。两者都须实现验证，不作为已有通用保证。

## 1. 前台资格与旧送键撤销

**建议机制：** 保留一个宿主 STA，由它管理前台资格和按键 admission。组字结束只结束组字，不归还前台；真实失焦、关闭、导航立即撤销旧资格。排队键携带送键资格，重新聚焦不恢复旧队列。正常获取及受限一次 Alt 只出现在新授权入口，发送路径只检查实际前台和 STA 焦点，不调用 `Ensure` 抢回前台。外部调用返回后重新检查资格，不持队列锁跨原生调用。已送出的修饰键单独跟踪释放，不能与未发送旧键一起丢弃。

**已有证据：** 抑制过早归还后，真实拼音出现组字、提交；监督式 VR 中提交时宿主持有前台。原 STA 失焦阻断旧动作与撤销完成后一次回点已有阳性。旧队列会跨重新聚焦发送、持锁跨 `Send` 会阻塞撤销、整批丢弃会漏修饰键 up，也已有反例。见[宿主生命周期](host-lifecycle.md)。

**否定走法：** 每键获取／归还、按布尔 active 给旧队列重新放行、WndProc 等待页面、跨原生调用持锁，均不进入实现。

**已接受边界与协议：** 0058 允许同步窗口中新操作被拒绝；0060 将新请求起点固定为页面实际收到的明确输入事件。同步完成后才到 DOM 的排队原生输入可以生成新请求；已生成的旧页面请求和旧送键仍作废。按[撤销确认协议](foreground-refocus-protocol.md)先关闭 admission、定向 clear＋blur，收到当前文档与代次的清理答复后才允许页面开放；开放本身不 focus、不 Take、不补造请求。请求身份在事件入口固定，延后发送不重新标记。

**剩余风险：** 此协议未完成真实页面／STA 接线；首次打开的生产者、pointer／touch 覆盖及 Tab 配对候选仍须验证。清理回执不证明原生输入已排空，STA admission 也不能把全局 `SendInput` 原子绑定到 HWND。

**接线范围：** `CompositionSession.End`、批次完成和档案切换都须停止按组字归还前台；`HostWindow` 接原生失焦，`ImeHost` 接资格撤销。`KeyboardVisibilityPatch` 的关闭路径改为撤销，不再先排 Escape；`KeyboardPage` 的导航／不可用事件同样接撤销。失焦通知只清对应旧资格，不能清掉已建立的新期。

**验收：** 真实失焦后旧键和旧请求均不获取前台；同步窗口内可拒绝新操作，安全重开后可接受新操作；关闭／导航／快速回点不被旧通知破坏；修饰键全部释放。分别记录请求发布、STA 撤销、原生入口，不能把异步 Post 返回称为撤销完成。

## 2. 宿主文字与浏览器原生编辑顺序

**建议机制：** 在原 STA 消息泵中只执行一次 TSF `Test → Key` 消费链。普通文字只从宿主字符／提交结果交付，浏览器接收未消费的编辑与快捷键。按下归属保持到抬起，清理只释放已送达的键。Unity 侧用一个有界操作队列协调结果和编辑，结果等待实际脚本答复后才释放后续操作；停止时撤销队列，旧答复不能释放新队列。Enter 保留 [0052](../../adr/0052-broadcast-chatbox-previews-and-keep-native-submission.md) 的正式发送路径。

消息主循环与送键排空复用同一个处理入口，不能各做一次过滤。租约期间阻断原 WebView 的重复硬件转发，由宿主路由统一交付；退出时恢复。编辑键使用明确的命名键映射，不能把私有 `MapWebKey` 的枚举名回退当作通用转换。保留 modifier 生命周期；识别快捷键不能只看 keyup 时的修饰态。

**已有证据：** 直接给浏览器字符键再写宿主结果会重复插入。连续 A＋退格出现过跨 API 反序，等待文字执行答复后的固定游戏对照恢复空框。反向空退格＋A 的三组均通过，没有证明编辑答复必要。见[物理输入证据](host-lifecycle.md#证据物理输入)。

**否定走法：** Unity FIFO 等于浏览器执行完成、重复字符双路交付、用合成 DOM 按键代替原生编辑、把 keyup 当通用完成屏障，均不成立。

**编辑完成候选：** Unity 先在页面登记唯一待办编号，取得登记答复后才发原生编辑键；页面只观察实际命中的 native 事件，不合成编辑。对同步默认编辑，拟在匹配事件之后的独立页面任务读取正文和选区并回报，使用任务投递，不用 microtask 或固定睡眠推断完成。每个 repeat down 单独排队确认，不等整次物理 keyup；up 仍按已送出的 down 清理。剪贴板动作另匹配实际 copy／cut／paste 事件，不能用 V 的 keyup 提前结束粘贴。编号只用于本队列答复，不追溯输入法结果。

| 路径                       | 队列规则                                                                    |
| -------------------------- | --------------------------------------------------------------------------- |
| 文字                       | 实际插入函数完成并返回后放行；失焦丢弃也是一次完成。                        |
| 同步编辑／移动             | 匹配默认动作及任务后快照，再放行后续文字；快照包括值、选区和方向。          |
| 正常空操作                 | 同一完成路径答复“不变”；不要求必须出现 input 或正文变化。                   |
| 粘贴                       | 等实际 paste 处理边界；空剪贴板、拒绝与成功须分别验收，不能补插剪贴板内容。 |
| 停止／导航／异常／答复失效 | 取消当前队列，仅清理已送键；可能已执行的操作不重放。                        |
| 永久缺答复／容量耗尽       | 有界失败监测终止本次操作流并报告；期限不作为完成证据，不自动重试。          |

**尚未获证的前提：** 任务后观察是否覆盖安装版默认动作、原生事件与待办的关联、无事件的粘贴及 repeat 交错，均未通过集成验证。这个候选比 keyup 屏障具体，但不是已验证事实。协议只排序浏览器默认编辑与插件结果，不承诺排空语音、网络或任意应用任务。若候选不能覆盖验收，编辑通道不得发布，须回到设计评审；不静默缩减快捷键、改为 JavaScript 编辑或重放文字。

**验收：** 在同一实现队列覆盖非空退格／Delete、选区替换、方向键、Ctrl+A/C/V/Z、repeat、提前释放 Ctrl、停止和页面替换。粘贴由浏览器完成，不另插剪贴板文字。必须比较最终文本、选区和有效 undo／redo；提交成功或事件出现本身不算通过。

## 3. 当前 composer 的结果显示与丢弃

**建议机制：** 三类结果统一走当前焦点交付入口。处理时检查当前页面有效、composer 存在且实际聚焦；否则立即丢弃。页面执行时再检查本地焦点。删除 `_view` 的跨失焦缓存与 `Attach` 旧显示重放；隐藏、inactive、导航清除当前显示。业务调用遇到 missing 或未知答复即结束，不重注入重放该结果。页面初始化只建立接口，不补发旧文字、组字或候选。

预编辑按 0056 放在独立标签，不写正文和选区。提交只对当前选区执行一次原生 `insertText`，不调用 `.focus()`。按 0057 接受重新聚焦后新到的旧结果混入，不再维护结果来源、历史插入位置或原目标文档。

**已有证据：** 原生产缓存会在 inactive／Hidden 后经 `Attach` 再提交旧 view；完整页面在提交已拒绝时仍渲染候选。正文临时赋值还会破坏原生撤销，独立显示对照保留撤销。见[当前焦点丢弃缺口](late-commit.md#当前焦点丢弃缺口)和[组字显示](late-commit.md#已确认的组字显示)。

**否定走法：** 只保护 commit、不保护候选；失焦缓存等待 refocus；为写回临时聚焦；失败答复后重试插入，均不进入实现。

**剩余风险：** DOM 焦点与原生资格经异步消息更新，三处检查不是跨进程事务。结果可交付也不能授予送键资格。提交可能已执行但答复失败，记录未知结果而不补发。

**验收：** composer 持焦、另一控件持焦、缺失、隐藏、导航及快速 refocus 分别检查三类结果；被丢弃的结果之后不出现。候选和标签撤下不改正文，原生撤销有效。23:42 日语持焦复测已有组字和候选，Return 页面按下仍无宿主请求，地址修正不足以完成接线。先按[回车修复接线](return-key.md#建议修复接线)消除首次判定对模块加载的前置依赖，再验收真实请求、宿主判定和提交；不重复无阶段诊断的人工复测。

## 4. 原生异步清理与资源收尾

**已选后端：** 按 0059 保留单 STA／单宿主，采用单一 transitory 文档接收确定结果与当前组字。消费 result 范围而非让旧 End 请求读取／删除当前全文。候选仍走现有公开 TSF UI 通知；档案、语言栏和用户模式约束保持。

**已有证据：** 原处理器在受控旧 End→新组字次序下会提交并删除整个当前上下文；这不是仅靠页面丢弃能修复的问题。Transitory 已验证真实拼音结果、有限 result-only 消费、UTF-16 长范围与选区，以及有限取消／释放。见[原生清理记录](late-commit.md#原生侧来源身份)和[上下文记录](context-isolation.md)。

**取舍及代价：** 保留旧后端的备选及否决理由见 0059。新后端删除旧 End 清理推断，同时承担真实日语、候选和档案兼容的重新验收。

**共同寿命要求：** 结果丢弃不等于原生对象可以释放。退休先关闭新 admission，已进入的原生回调帧及挂起请求持有原生 owner；不能只在托管 delegate 内计数，因为返回后仍有原生续行。通知内只请求退休，实际销毁回到 owner STA 并避开仍在执行的原生帧。解绑、Pop、取消请求与实际最终 Release 分开记账。普通失焦走默认行为，不退休文档，不以 Escape、等待或空队列强制结算。

**剩余风险与验收：** 新后端的真实日语、候选、档案切换及默认失焦仍需实现后验证。有限析构计数不是任意 TIP 完成合同；移除托管 token 也不是回调完成屏障。验收必须包含实际 shim 回调内请求退休、仍挂起的 edit-session、关闭／退出及最终析构，禁止在已删除对象的续行上做崩溃式试验。

## 已接受的取舍与实施责任

- **焦点行为：** 0058 已接受同步窗口中新操作被拒绝、需要重新操作，不保证至多多点一次。0060 已接受以页面收到明确操作为界，包括同步后才到页面的排队原生输入；旧页面请求和旧资格工作仍作废。撤销确认协议须接线验证。
- **原生后端：** 0059 已接受单 STA、单宿主、单 transitory 文档；实现后重新验收日语、候选、档案切换、默认失焦与原生收尾。
- **排序责任：** 推荐上述事件任务确认候选，并把未获证前提列为接通正式路由前的实施门槛。它保留 0054 的全部验收范围，不把 keyup、任务答复或试验计数当通用完成保证。

## 实施顺序与验收门槛

1. 依据 0058／0059／0060 接撤销确认协议，固定排序候选的正常、空操作和失败路径；接线及必要前提未通过时不接通正式入口。
2. 先实现当前焦点交付与独立组字显示，删除缓存／业务重放；补完整页面回归。
3. 实现单 STA 资格、撤销和已送键清理，再接入已接受的获取策略；前台协议未闭合时不宣称符合 0050。
4. 实现选定原生后端和安全退休，接入一个文字／编辑队列；各自测试实际回调与取消路径。
5. 完成拼音、日语、小狼毫、US 的真实页面验收，再做一次有明确问题、门禁已验证的 VR 会话。

| 实施门槛       | 必须看到的结果                                                                    | 失败时的处理                                  |
| -------------- | --------------------------------------------------------------------------------- | --------------------------------------------- |
| 当前焦点交付   | 三类结果在失焦时均丢弃，refocus 不重放；标签不破坏正文撤销。                      | 修交付入口，不加缓存兜底。                    |
| 资格与撤销     | 原 STA 撤销后不再送旧键／获取；已送修饰键释放，新操作符合已接受的焦点行为。       | 不接通新获取入口。                            |
| 顺序与默认动作 | 非空编辑、空操作、粘贴、repeat 交错及有效 undo／redo 均符合原生对照。             | 排序候选退回评审，不删减验收范围。            |
| 原生收尾       | 回调内请求退休后原生续行仍安全，挂起请求取消／完成，实际 owner／sink 析构可核对。 | 不发布后端替换，不以托管 token 消失代替释放。 |
| 真实页面与 VR  | 当前构建的拼音／日语／小狼毫／US、Return、默认失焦通过一次有明确问题的集中会话。  | 按来源记录差异，先修诊断门禁再申请人工复测。  |

本稿交付机制、已接受取舍、实施顺序和验收门槛，不声称产品修复完成。安全重开协议的事件覆盖与真实往返、排序候选的未获证前提均须在实施时验证；两者不能改称已有保证。没有必要先重复全部真机测试。
