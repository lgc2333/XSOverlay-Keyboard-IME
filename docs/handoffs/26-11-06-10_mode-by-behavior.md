# 输入法模式：决定与下一步（2026-11-06）

接续 [26-11-06-9](./26-11-06-9_host-switch-refactor.md)。上一轮的宿主在 VR 里首次实测失败：打不出中文。这一轮定位原因、跑通真机端到端，最后把「插件该不该自己切中英」这件事定了下来。

## 现状一句话

代码停在 HEAD（旧行为，见下），[0025](../adr/0025-respect-ime-mode.md) 已按新决定改写并提交；实验阶段的实现还没开始。

## 决定

[0025](../adr/0025-respect-ime-mode.md)：**插件不切换中英**。输入法是什么状态，按键就按什么状态走；中英由用户显式切换。判据读 IMM32 的 `ImmGetConversionStatus` + `IME_CMODE_NATIVE`。

## 为什么

旧判据「读宿主报告的模式，只在直通时翻转」不成立。真机日志：

- 组字进行中，模式回调仍反复报 `Passthrough`；
- 游戏刚启动、小狼毫是英文时，首键读到 `Composing`，插件于是不翻转，`n` 被原样插成英文；
- 那个会话没组字也没结束，闸门进入「只收提交键」，后面的字母全被拒，页面自己打进英文——用户看到的就是「打不了中文」。

## 调研结论

- TSF 转换模式隔间：小狼毫只在该隔间自身变化时刷新，值与真实中英无关；IngameIME 读的就是它。
- TSF 开闭隔间：小狼毫在该隔间回调里把 `ascii_mode` 取反后 `_SetKeyboardOpen(true)` 写回 1，隔间常住 1，值只在变化瞬间有信号。
- 语言栏按钮：`GetStatus` 只有启用/隐藏标志，`GetText` 是固定串，中英只体现在图标里。
- IMM32 `IME_CMODE_NATIVE`（CUAS 层，进程内可读）：实测跟随真实状态——英文态 `conversion=0xca0 native=False`，切中文后 `0xca1 native=True`，七次采样一致；`ImmGetOpenStatus` 反而与中英相反，不能用。

## 当前代码与构建

- 工作区代码已退回 HEAD：仍是「读模式 + 直通时翻转一次并重放」的旧行为，与 0025 不一致。
- 游戏里跑的是这轮早些时候部署的旧构建（自动翻转版），与源码一致，但与 0025 不一致；实验阶段会重新构建部署。
- 本轮真机实测在旧构建上完成，下表留作行为基线：

| 场景                         | 结果                                                   |
| ---------------------------- | ------------------------------------------------------ |
| 首键字母（输入法本来是英文） | 翻转一次并重放，组字串 `ni hao`，空格提交 `你好`       |
| 连续两次组字                 | 第二次不再翻转，直接组字提交                           |
| 数字键 2 选词                | 提交第二候选 `👋`                                      |
| PageDown 后空格              | 提交翻页后的首候选（宿主 `依`，游戏 `已`）             |
| 回车                         | 提交原始编码 `nihc`                                    |
| Esc                          | 取消组字并结束会话，前台归还；随后再打仍出 `你好`      |
| 退格后空格                   | 组字串退回 `ni h`，提交 `你好`                         |
| 空格后逗号                   | 先提交 `你好`，再提交 `，`                             |
| 左方向后回车                 | 组字串退回原码 `nihc`，只提交光标前的 `ni`             |
| Tab 后空格                   | 组字串退回原码 `nihc`，空格固定前缀 `你hao` 后继续组字 |
| Shift                        | 不被接管，交给页面；空格仍提交 `你好`                  |
| 首键为数字 2                 | 数字原样插入，不翻转；随后字母组字并提交               |

写回只有页面输入框持有焦点时才插入：焦点在时为 `writeback '你好' -> inserted`，不在时页面以 `focus-lost` 拒收。

## 下一步实验（按顺序）

1. **不自动翻转**：删掉翻转与重放；输入法把字符原样插进来时写回并立即结束会话（不再逐键抢前台）。
2. **接管判定**：读 `IME_CMODE_NATIVE` 决定是否接管字符键——原生态才接管，组字中接管所有键，其余还给页面。判据读不到时不接管。
3. **页面控件**：加一个中英切换按钮，点击时写一次开闭隔间（翻转开关），再用 IMM 确认新状态并回报页面。

验收沿用上表：中文态各项不变；新增「英文态敲字母不吞键、直接变成英文」。自动化方法见下。

## 环境要点

- 游戏以管理员权限运行而 Steam 不是：普通 shell 停不掉它。用 Steam 客户端的「停止」（库 → 游戏页 → 停止 → 确认），由以 `LocalSystem` 运行的 Steam Client Service 终结进程，然后再部署。
- 游戏内自动化：游戏自己的 websocket（`ws://127.0.0.1:42070`）发 `SendKeyboardEvent` 即与键盘页同一条路径；键盘 overlay 要先钉住（`KeyboardOverlayAction pin`）才允许 `RequestKeyboardInputFocus`；写回要页面输入框有焦点，用 Tab 把焦点送进页面。
- 不戴 VR 的宿主验证：把 `Ime/`、`Takeover/`、`Interop/`、`Input/` 编进控制台程序，喂与键盘页相同的 `PageKey`，输入法用真实小狼毫。本轮这类工具都在临时目录，未入库。
